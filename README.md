# jockie的小宇宙

以写作为中心的个人博客。Astro 静态生成，GitHub Pages 托管，Markdown 管理文章；不需要维护服务器。

## 本地运行

使用 Node.js 24 LTS：

```sh
npm ci
npm run dev
```

默认本地地址为 `http://127.0.0.1:4321/my-universe/`，以终端实际输出为准。开发模式会显示草稿，并明确标注；正式构建会排除草稿。

搜索索引在构建时生成，要查看完整搜索体验：

```sh
npm run build
npm run preview
```

预览默认地址为 `http://127.0.0.1:4321/my-universe/`。本地预览不会请求真实阅读计数或 giscus 评论。

当前机器也准备了未提交的便携 Node，PowerShell 中可临时使用：

```powershell
$env:PATH=(Join-Path (Get-Location) '.tools\node-v24.22.2-win-x64')+';'+$env:PATH
$env:ASTRO_TELEMETRY_DISABLED='1'
npm run dev
```

## 游戏模块

首页「去玩个小游戏」或导航「游戏」进入 `/games/`，目前可玩三骰猜大小和 2048 星球合成。游戏目录由 `src/lib/games.ts` 管理，后续可添加其他游戏。

2048 位于 `/games/2048/`：方向键、棋盘滑动或方向按钮控制整盘，合并相同数字，合成 2048 后可继续探索。棋盘、当前分数、最高分与步数自动保存在此浏览器；新游戏清空本局并保留最高分。无法使用本地存储时仍可游玩，但刷新会丢失进度。构建后运行 `npm run test:2048` 可验证键盘、动画、真实触屏、存档和移动端布局。

默认 1,000 虚拟金币，点击「设定金币 / 重新开始」可设 1～1,000,000 初始金币并清空历史。选筹码或输入金额后，点击大小／总点数下注；同一位置可累计，一局可押多个位置。「清空下注」撤回本局待下注，「下注并开骰」一次结算。

小为 4～10，大为 11～17，豹子时大小通输；押总点数遇到豹子仍按总和结算。页面标明净赢倍数，中奖另退本金。进度保存在浏览器 localStorage，刷新可继续；不跨设备同步，没有充值、提现或真钱交易。开骰记录包含骰子点数、大小／豹子、下注、返还、盈亏及余额；统计包含全部历史和并列最高频点数。

验证游戏交互：`node scripts/dice-browser-smoke.mjs`（先运行 `npm run build`，需已安装 Chrome）；输出桌面和手机截图到 `.tools/screenshots/`。

## 阅读量如何实现

文章详情页通过 **不蒜子（Busuanzi）** 显示该页面的访问次数，不显示全站访问量。入口是 `PageViews.astro`，加载逻辑在 `src/scripts/article-services.ts`。

1. 页面先显示 `阅读 — 次`。只有正式构建、当前来源为配置的 HTTPS 正式域名时，才加载 `https://busuanzi.ibruce.info/busuanzi/2.3/busuanzi.pure.mini.js`；本地开发和本地预览不会计数。
2. 服务脚本使用 JSONP 请求计数。目前引入的不蒜子脚本会为它创建的 JSONP 请求设置 `no-referrer-when-downgrade`，向 HTTPS 统计服务提供完整文章地址，让服务按文章路径区分 PV，而不是把所有文章归到同一个域名；浏览器检查也验证了这个请求携带完整路径。
3. 服务返回数字后替换占位。12 秒后仍无结果，提示统计暂不可用；晚到的成功响应仍可正常显示。服务加载失败不会影响阅读。

**统计口径是 PV（页面访问次数）**，刷新或重复打开也可能增加；它不等于独立读者数，也不能证明读完了文章。数据保存在第三方服务，不写回 GitHub、不使用浏览器本地数字伪造计数。网络、浏览器隐私策略和拦截器会影响统计。改变域名或文章路径可能产生新的统计记录，旧博客的历史计数不会随 Markdown 一起迁移。

### 重新打包、部署会改变阅读量吗？

**重新打包或部署本身不会清零、重置或增加阅读量。** 只要正式站点的域名、基础路径和文章地址保持不变，访问时就会继续读取对应地址在不蒜子服务中的累计记录。正常访问仍会使数字变化，所以它不意味着“重新部署前后显示的数字必须完全一样”；部署后自己打开正式文章检查，也可能被计为一次访问。

构建文件和阅读量数据分别存放，流程如下：

1. **构建阶段：** Astro 把 Markdown、模板和样式生成到 `dist/`。文章 HTML 只包含 `阅读 — 次` 的占位和加载脚本，不包含一个等待下次构建更新的阅读量快照；构建过程不请求不蒜子计数接口。
2. **访问阶段：** 访客在浏览器打开正式文章，`article-services.ts` 校验当前地址是配置的 HTTPS 正式来源后，再加载不蒜子脚本。该脚本向统计服务发起请求；当前接入通过请求的 Referer 提供完整文章地址，由服务识别页面、处理本次访问并返回累计 PV。页面加载外部脚本时浏览器自动发送的来源信息，与访客“从哪个网站点进来”是两个概念。
3. **显示阶段：** 不蒜子把返回值写入 `busuanzi_value_page_pv`，页面监听到有效数字后隐藏占位并显示计数。重新部署会替换静态文件，但不会删除第三方服务器上的记录；JS/CSS 文件名中的构建哈希变化也不会改变文章地址。

例如，文章一直使用 `https://jockiepeng.github.io/my-universe/posts/ai-tools-setup/`，修改正文、标题、配图或样式后再部署，仍会读取这个地址对应的累计阅读量。项目没有向不蒜子发送重置请求的代码，也没有把阅读量存入 Markdown、`dist/` 或浏览器 localStorage；计数保存、页面地址的具体归一化及去重规则由第三方服务决定。

| 操作或情况 | 对阅读量的影响 |
| --- | --- |
| 修改文章内容或页面样式，保持文章地址不变后重新部署 | 不会因部署而重置，继续使用原有统计 |
| 删除本地 `dist/` 后重新构建，或重新运行 GitHub Actions 发布 | 不会删除不蒜子服务器上的记录 |
| 打开、刷新正式文章，或部署后访问正式地址检查 | 可能再次计为 PV，数字正常增长 |
| 本地开发、`npm run preview`，或访问未匹配配置的预览域名 | 当前实现不加载计数脚本，不记录阅读量 |
| 更换域名、`BASE_PATH`、文章 slug，或重命名文件导致文章路径变化 | 可能被识别为新页面；重定向和重新部署不会自动把旧地址计数迁移到新地址 |
| 第三方服务不可用、脚本被拦截，或浏览器没有发送可用的页面地址 | 可能无法显示或正确区分页面计数；看到 `—` 不等于历史数据清零 |

维护时应尽量保持公开文章地址稳定。服务端数据的长期保存由不蒜子负责，本项目没有独立的阅读量数据库备份；第三方调整或丢失记录也不能通过重新构建网站恢复。

## 评论如何实现

评论使用 **[giscus](https://giscus.app/zh-CN)**，实际数据保存在指定 GitHub 仓库的 **Discussions**，无需自建后端或数据库。`Comments.astro` 输出配置，`article-services.ts` 在评论区域进入视口附近（200px）时才加载 giscus iframe；同样仅在正式域名启用。

- 使用 `pathname` 映射和严格匹配：同一文章路径对应同一条 Discussion。首次打开没有评论时不会立即新建讨论，读者第一次实际评论时由 giscus 创建。
- 评论者通过 GitHub 登录，评论、回复与表情由 GitHub／giscus 管理。仓库管理者可在 Discussions 中管理内容。
- 文章默认开启评论；贴图默认关闭，也可用 frontmatter 的 `comments: true/false` 单独覆盖。缺少仓库或分类 ID 时显示“评论暂未开放”。
- 评论跟随深浅色切换；加载失败时保留前往 Discussions 的入口。更改文章路径或评论仓库后需处理原讨论映射，Markdown 迁移不会自动搬运旧评论。

下面的配置值在 **构建时** 写入页面，属于公开标识，不是令牌；修改 Actions Variables 后需要重新运行构建部署。

## 首页背景

首页使用固定在视口上的 **整页 WebGL 动态背景**，滚动后仍覆盖全屏，不请求外部视频、动画素材或第三方运行库。采用选型原型中的星系漫游（旋臂／星尘）、极光之境（光幕）与日落海面（波浪／倒影）。文章列表使用衬底保证可读性；「随想」放在首页文章列表顶部、最近记录标题上方，文章详情不包含动画画布。

导航中可换场景、选择开场方式、重播，或恢复今日自动组合；页脚可关闭动态。主题与动态偏好长期保存在当前浏览器；手动选择背景／开场只在当天生效。画布约 30fps、分辨率不超过 CSS 像素且宽度上限 1100，切到后台或系统启用“减少动态效果”时停止逐帧绘制；无 WebGL 或图形上下文丢失时保留静态渐变，无 JavaScript 时直接阅读博客。

### 日期尾号与入场规则

`src/lib/motion.mjs` 使用北京时间当天「日」数的个位数（0–9）。例如 2、12、22 日使用同一默认组合，不使用访客本地时区。算法以固定种子打乱三种背景 × 两种开场的六个组合，再映射至十个尾号，因此每台设备结果一致、同日刷新不变化，全部六个组合都能出现。

| 日期尾号 | 背景 | 开场 |
| --- | --- | --- |
| 0、6 | 日落海面 | 粒子汇聚 |
| 1、7 | 极光之境 | 星门开启 |
| 2、8 | 星系漫游 | 星门开启 |
| 3、9 | 日落海面 | 星门开启 |
| 4 | 极光之境 | 粒子汇聚 |
| 5 | 星系漫游 | 粒子汇聚 |

跨北京时间午夜后，页面自动采用新尾号组合，前一天的手动选择过期；不会重新弹出开场打断阅读。同一尾号可重复出现，例如 31 日和下月 1 日组合相同。

首次进入首页先播放约 4.3 秒开场，结束后显示“进入博客”，始终可跳过或按 Escape 进入。进入后用 `sessionStorage` 记录当天已看过，同一标签页当天刷新／返回首页不重复播放；导航中的“重播开场”可再次体验。新会话或次日首次访问首页会再播放，文章、归档和首页锚点直达不拦截。关闭动态或减少动态效果时立即显示静态结尾与进入按钮；禁用存储时仍能进入和手动切换，但刷新后不保留记录。

背景使用原生 WebGL，开场粒子使用 Canvas 2D，星门和文字出场用 CSS。开场期间正文与导航 `inert`，键盘焦点留在开场内；进入后恢复正文焦点和正常滚动。

设计调研参考：[Anthony Fu](https://antfu.me/) 的个人站与生成艺术方向、[Josh Comeau 的博客复盘](https://www.joshwcomeau.com/blog/how-i-built-my-blog-v2/) 中的首页生成式彩虹、[Butterfly 官方背景特效配置](https://butterfly.js.org/posts/4aa8abbe/)。本项目独立实现场景绘制。

## 更新「随想」句子

编辑 [`src/data/daily-quotes.json`](src/data/daily-quotes.json)，每条填写永久唯一的 `id`、句子 `text` 和开始参与选取的北京时间日期 `availableFrom`。页面只显示「随想」与句子，不显示日期或来源。当前共 24 条文案，其中新增 16 条从 2026-11-03 开始参与选取。更新后提交并通过 GitHub Actions 重新构建即可；不需要后端。

算法在 `src/lib/daily-quote.mjs`：先筛选 `availableFrom <= 当天日期` 的句子，再按 `id` 固定排序；以 **北京时间的年月日** 为种子，用 FNV-1a 哈希和 Mulberry32 混合得到固定数值，映射到当天的候选列表。同一天刷新、换浏览器或重新部署均得到相同结果；跨日重新选择，可能连续选到同一句。页面打开到午夜也会自动更新，从后台返回时校正日期。无候选句子时显示占位文案，只有一个候选时显示该条。无 JavaScript 时显示构建当天的文案，不能自动跨日切换。

**新增而不改变当天及历史选择：** 新句子的 `availableFrom` 必须晚于实际发布日期（北京时间），例如 2026-11-02 发布时，设为 2026-11-03 或更晚。日期是固定写入文件的值，不会在部署时自动重算。新句子从该日起进入候选池，不保证当天一定被选中；同日所有读者的句子一致。

```json
{ "id": "window-light", "text": "午后的光挪过桌面，才发现自己已经安静地读了很久。", "availableFrom": "2026-11-03" }
```

请为每条新句子使用新 ID，并把示例日期改成实际发布日之后的日期。已有句子的 `id`、`text`、`availableFrom` 保持不变；调整 JSON 中的排列顺序不影响结果。删除旧句子、修改旧内容或把新句子的日期填到今天或过去，可能改变既有结果。本次从旧算法迁移到按 ID 排序，可能改变升级当天的原选择；上述稳定性保证从这版算法开始。缺失或非法的起始日期、重复 ID 会直接使构建失败。

文案会随静态站点发布到浏览器，请将准备公开的内容放在这个文件中。

## GitHub Pages 发布

本仓库对应的默认站点配置是 `https://jockiepeng.github.io/my-universe/`；该配置不代表已经上线。

1. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
2. 将代码提交到 `main`，或者在 `main` 上手动运行 **Check and publish blog** 工作流。
3. 工作流自动测试、检查、构建、生成搜索索引并发布。PR 只检查，不发布。

项目路径会从仓库名称推导，`*.github.io` 用户站点使用根路径。自定义域名时，在仓库 Actions **Variables** 设置 `SITE_URL`（例如 `https://blog.example.com`）和 `BASE_PATH`（根路径填 `/`），并在 Pages 中绑定域名。需要 CNAME 时可放入 `public/CNAME`。

本地可通过环境变量 `SITE_URL`、`BASE_PATH` 覆盖构建地址。配置默认仍为本仓库的项目站点。

## 开启评论

1. 在公开仓库中开启 **Discussions**。
2. 通过 [giscus 配置页](https://giscus.app/zh-CN) 安装 GitHub App，并选择仓库与评论分类。
3. 将生成的公开值填写到仓库 Actions **Variables**：`PUBLIC_GISCUS_REPO`、`PUBLIC_GISCUS_REPO_ID`、`PUBLIC_GISCUS_CATEGORY`、`PUBLIC_GISCUS_CATEGORY_ID`。
4. 重新构建发布。访客使用 GitHub 账号发表评论，管理者在 Discussions 中管理评论。

配置缺失时文章显示“评论暂未开放”。评论按稳定文章 pathname 关联，更改 slug、域名或基础路径时应规划旧讨论的迁移。

## 阅读量

文章详情显示“阅读 — 次”，正式站点从 [不蒜子](https://busuanzi.ibruce.info/) 获取真实页面浏览次数；收到数字后才替换占位。只展示文章阅读量，不展示全站统计。它不是独立读者人数，刷新和重复访问可能再次计数。

只有 HTTPS 且地址匹配构建时的正式域名，才会加载计数。第三方服务不可用时保留占位，文章仍能阅读。发布后需要验证服务在实际域名上的可用性。

重新打包、部署不会重置服务端计数；完整流程、地址变更的影响和维护注意事项见[重新打包、部署会改变阅读量吗？](#重新打包部署会改变阅读量吗)。

- `src/styles/global.css`：原型的视觉实现。
- `output/prototypes/`：前期交互原型，供设计对照；正式网站不依赖此目录。
