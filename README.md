# jockie的小宇宙

以写作为中心的个人博客。Astro 静态生成，GitHub Pages 托管，Markdown 管理文章；不需要维护服务器。

## 本地运行

使用 Node.js 24 LTS：

```sh
npm ci
npm run dev
```

默认本地地址为 `http://127.0.0.1:4321/my-universe/`，以终端实际输出为准。开发模式会显示草稿，并明确标注；正式构建会排除草稿。

搜索索引在构建时生成，要查看完整搜索体验：

```sh
npm run build
npm run preview
```

预览默认地址为 `http://127.0.0.1:4321/my-universe/`。本地预览不会请求真实阅读计数或 giscus 评论。

当前机器也准备了未提交的便携 Node，PowerShell 中可临时使用：

```powershell
$env:PATH=(Join-Path (Get-Location) '.tools\node-v24.22.2-win-x64')+';'+$env:PATH
$env:ASTRO_TELEMETRY_DISABLED='1'
npm run dev
```

## 界面语言

默认中文，右上角点击 `EN` 切换英文，点击 `中文` 切回。语言记录在浏览器的 `little-universe-language-v1`，切页或刷新继续使用；浏览器禁用存储时仍可在当前页面切换。切换不会刷新页面、清空下注或改变工具里的输入。

导航、介绍、分类标签、日期、搜索、游戏规则与提示、工具和分享图片均支持英文。英文「随想」按当天日期从现有 200 条英文原文中选句，作者与出处同步显示英文；求签的 196 支签诗与解读都有英文版本。

公共、游戏、工具翻译分别维护于 `src/i18n/site.mjs`、`games.mjs`、`tools.mjs`；使用原中文完整短句作键，动态值使用 `{0}`、`{1}`。`src/scripts/language.ts` 处理界面文本和无障碍属性，`src/lib/i18n.mjs` 的 `t()` 用于画布等非 DOM 输出。文章内容和用户寄语使用 `data-i18n-skip` 保护；局部同字异义可使用 `data-i18n-en`。新增界面文案时应同时添加翻译。英文签文单独维护在 `src/data/fortune-texts.en.json`。

构建后运行 `npm run test:i18n`，验证全站英文覆盖、语言记忆、动态结果、文章与输入保护、分享图片文字和手机布局。

## 阅读量如何实现

文章详情页通过 **不蒜子（Busuanzi）** 显示该页面的访问次数，各页面导航以「博客累计浏览量」展示全站页面浏览次数。文章入口是 `PageViews.astro`，导航入口是 `VisitorInfo.astro`，共享加载逻辑在 `src/scripts/page-views.ts`；所有正式页面都参与全站计数，每次打开只加载一次统计脚本，文章 PV 与全站 PV 共用同一次请求。

1. 页面先显示 `阅读 — 次`。只有正式构建、当前来源为配置的 HTTPS 正式域名时，才加载 `https://busuanzi.ibruce.info/busuanzi/2.3/busuanzi.pure.mini.js`；本地开发和本地预览不会计数。
2. 服务脚本使用 JSONP 请求计数。目前引入的不蒜子脚本会为它创建的 JSONP 请求设置 `no-referrer-when-downgrade`，向 HTTPS 统计服务提供完整文章地址，让服务按文章路径区分 PV，而不是把所有文章归到同一个域名；浏览器检查也验证了这个请求携带完整路径。
3. 服务返回数字后替换占位。12 秒后仍无结果，提示统计暂不可用；晚到的成功响应仍可正常显示。服务加载失败不会影响阅读。

**统计口径是 PV（页面访问次数）**，刷新或重复打开也可能增加；它不等于独立读者数，也不能证明读完了文章。数据保存在第三方服务，不写回 GitHub、不使用浏览器本地数字伪造计数。网络、浏览器隐私策略和拦截器会影响统计。改变域名或文章路径可能产生新的统计记录，旧博客的历史计数不会随 Markdown 一起迁移。

### 重新打包、部署会改变阅读量吗？

**重新打包或部署本身不会清零、重置或增加阅读量。** 只要正式站点的域名、基础路径和文章地址保持不变，访问时就会继续读取对应地址在不蒜子服务中的累计记录。正常访问仍会使数字变化，所以它不意味着“重新部署前后显示的数字必须完全一样”；部署后自己打开正式文章检查，也可能被计为一次访问。

构建文件和阅读量数据分别存放，流程如下：

1. **构建阶段：** Astro 把 Markdown、模板和样式生成到 `dist/`。文章 HTML 只包含 `阅读 — 次` 的占位和加载脚本，不包含一个等待下次构建更新的阅读量快照；构建过程不请求不蒜子计数接口。
2. **访问阶段：** 访客在浏览器打开正式页面，`page-views.ts` 校验当前地址是配置的 HTTPS 正式来源后，再加载不蒜子脚本。该脚本向统计服务发起请求；当前接入通过请求的 Referer 提供完整页面地址，由服务识别页面、处理本次访问并返回页面与全站累计 PV。页面加载外部脚本时浏览器自动发送的来源信息，与访客“从哪个网站点进来”是两个概念。
3. **显示阶段：** 不蒜子把返回值写入 `busuanzi_value_page_pv`，页面监听到有效数字后隐藏占位并显示计数。重新部署会替换静态文件，但不会删除第三方服务器上的记录；JS/CSS 文件名中的构建哈希变化也不会改变文章地址。

例如，文章一直使用 `https://jockiepeng.github.io/my-universe/posts/ai-tools-setup/`，修改正文、标题、配图或样式后再部署，仍会读取这个地址对应的累计阅读量。项目没有向不蒜子发送重置请求的代码，也没有把阅读量存入 Markdown、`dist/` 或浏览器 localStorage；计数保存、页面地址的具体归一化及去重规则由第三方服务决定。

| 操作或情况 | 对阅读量的影响 |
| --- | --- |
| 修改文章内容或页面样式，保持文章地址不变后重新部署 | 不会因部署而重置，继续使用原有统计 |
| 删除本地 `dist/` 后重新构建，或重新运行 GitHub Actions 发布 | 不会删除不蒜子服务器上的记录 |
| 打开、刷新正式文章，或部署后访问正式地址检查 | 可能再次计为 PV，数字正常增长 |
| 本地开发、`npm run preview`，或访问未匹配配置的预览域名 | 当前实现不加载计数脚本，不记录阅读量 |
| 更换域名、`BASE_PATH`、文章 slug，或重命名文件导致文章路径变化 | 可能被识别为新页面；重定向和重新部署不会自动把旧地址计数迁移到新地址 |
| 第三方服务不可用、脚本被拦截，或浏览器没有发送可用的页面地址 | 可能无法显示或正确区分页面计数；看到 `—` 不等于历史数据清零 |

维护时应尽量保持公开文章地址稳定。服务端数据的长期保存由不蒜子负责，本项目没有独立的阅读量数据库备份；第三方调整或丢失记录也不能通过重新构建网站恢复。

## 评论如何实现

评论使用 **[giscus](https://giscus.app/zh-CN)**，实际数据保存在指定 GitHub 仓库的 **Discussions**，无需自建后端或数据库。`Comments.astro` 输出配置，`article-services.ts` 在评论区域进入视口附近（200px）时才加载 giscus iframe；同样仅在正式域名启用。

- 使用 `pathname` 映射和严格匹配：同一文章路径对应同一条 Discussion。首次打开没有评论时不会立即新建讨论，读者第一次实际评论时由 giscus 创建。
- 评论者通过 GitHub 登录，评论、回复与表情由 GitHub／giscus 管理。仓库管理者可在 Discussions 中管理内容。
- 文章和贴图默认开启评论，也可用 frontmatter 的 `comments: true/false` 单独覆盖。缺少仓库或分类 ID 时显示“评论暂未开放”。
- 评论跟随深浅色切换；加载失败时保留前往 Discussions 的入口。更改文章路径或评论仓库后需处理原讨论映射，Markdown 迁移不会自动搬运旧评论。

下面的配置值在 **构建时** 写入页面，属于公开标识，不是令牌；修改 Actions Variables 后需要重新运行构建部署。

## 首页背景

首页使用固定在视口上的 **整页 WebGL 动态背景**，滚动后仍覆盖全屏，不请求外部视频、动画素材或第三方运行库。采用选型原型中的星系漫游（旋臂／星尘）、极光之境（光幕）与日落海面（波浪／倒影）。文章列表使用衬底保证可读性；「随想」放在首页文章列表顶部、最近记录标题上方，文章详情不包含动画画布。

导航中可换场景、选择开场方式、重播，或恢复今日自动组合；页脚可关闭动态。主题与动态偏好长期保存在当前浏览器；手动选择背景／开场只在当天生效。画布约 30fps、分辨率不超过 CSS 像素且宽度上限 1100，切到后台或系统启用“减少动态效果”时停止逐帧绘制；无 WebGL 或图形上下文丢失时保留静态渐变，无 JavaScript 时直接阅读博客。

### 日期尾号与入场规则

`src/lib/motion.mjs` 使用北京时间当天「日」数的个位数（0–9）。例如 2、12、22 日使用同一默认组合，不使用访客本地时区。算法以固定种子打乱三种背景 × 两种开场的六个组合，再映射至十个尾号，因此每台设备结果一致、同日刷新不变化，全部六个组合都能出现。

| 日期尾号 | 背景 | 开场 |
| --- | --- | --- |
| 0、6 | 日落海面 | 粒子汇聚 |
| 1、7 | 极光之境 | 星门开启 |
| 2、8 | 星系漫游 | 星门开启 |
| 3、9 | 日落海面 | 星门开启 |
| 4 | 极光之境 | 粒子汇聚 |
| 5 | 星系漫游 | 粒子汇聚 |

跨北京时间午夜后，页面自动采用新尾号组合，前一天的手动选择过期；不会重新弹出开场打断阅读。同一尾号可重复出现，例如 31 日和下月 1 日组合相同。

首次进入首页先播放约 4.3 秒开场，结束后显示“进入博客”，始终可跳过或按 Escape 进入。进入后用 `sessionStorage` 记录当天已看过，同一标签页当天刷新／返回首页不重复播放；导航中的“重播开场”可再次体验。新会话或次日首次访问首页会再播放，文章、归档和首页锚点直达不拦截。关闭动态或减少动态效果时立即显示静态结尾与进入按钮；禁用存储时仍能进入和手动切换，但刷新后不保留记录。

背景使用原生 WebGL，开场粒子使用 Canvas 2D，星门和文字出场用 CSS。开场期间正文与导航 `inert`，键盘焦点留在开场内；进入后恢复正文焦点和正常滚动。

设计调研参考：[Anthony Fu](https://antfu.me/) 的个人站与生成艺术方向、[Josh Comeau 的博客复盘](https://www.joshwcomeau.com/blog/how-i-built-my-blog-v2/) 中的首页生成式彩虹、[Butterfly 官方背景特效配置](https://butterfly.js.org/posts/4aa8abbe/)。本项目独立实现场景绘制。

## 更新「随想」句子

编辑 [`src/data/daily-quotes.json`](src/data/daily-quotes.json)，每条填写永久唯一的 `id`、句子 `text` 和开始参与选取的北京时间日期 `availableFrom`。首页「随想」正文只用一个段落：外国句子显示为「英语底本原文（中文译文）」，括号紧接原文；中国古代句子显示简体中文原句。正文不设原文或译文标签，也不展示译文与版本说明。下方以纯文字标明作者与作品，不提供链接或跳转。数据与核查文档中的 `sourceUrl` 继续保留，供核对来源。当前共 500 条：300 条中国古代名句、200 条外国作品摘句，已整体替换原有 24 条生成随想。更新后提交并通过 GitHub Actions 重新构建即可；不需要后端。

全部内容见[随想名言清单](docs/daily-quotes.md)。数据还保存 `author`（作者或明确标注的典籍署名）、`source`（作品及篇章）、`sourceUrl`（原文来源）、`original`（所据底本原句）、`originalLanguage`（底本语言）、`category`（中国古代／外国），必要时用 `note` 说明异文、角色台词或归属问题。外国引文的 `translation` 标明本站中文翻译及所据历史英译者，不冒用已有中文译本。`evidenceSource` 对应[来源校验记录](docs/data/daily-quote-source-audit.json)中的实际获取方式、版本与 SHA-256。

这次整体替换的 500 条均从 `2026-01-01` 起可选，因此原有日期对应的句子会改变；后续新增再按下述未来日期规则处理。新增或修改内容时，一并更新完整清单与出处；须找到原著中的对应文字，不以无出处的网络语录作为核验依据。

算法在 `src/lib/daily-quote.mjs`：先筛选 `availableFrom <= 当天日期` 的句子，再按 `id` 固定排序；以 **北京时间的年月日** 为种子，用 FNV-1a 哈希和 Mulberry32 混合得到固定数值，映射到当天的候选列表。同一天刷新、换浏览器或重新部署均得到相同结果；跨日重新选择，可能连续选到同一句。页面打开到午夜也会自动更新，从后台返回时校正日期。无候选句子时显示占位文案，只有一个候选时显示该条。无 JavaScript 时显示构建当天的文案，不能自动跨日切换。

**新增而不改变当天及历史选择：** 新句子的 `availableFrom` 必须晚于实际发布日期（北京时间），例如 2026-11-02 发布时，设为 2026-11-03 或更晚。日期是固定写入文件的值，不会在部署时自动重算。新句子从该日起进入候选池，不保证当天一定被选中；同日所有读者的句子一致。

```json
{ "id": "unique-author-work-id", "text": "从所列原著核对后的完整句子", "author": "真实作者或说话人", "source": "作品与篇章", "sourceUrl": "https://原文来源地址", "original": "实际底本原句", "originalLanguage": "zh", "category": "中国古代", "availableFrom": "2026-11-05" }
```

请为每条新句子使用新 ID，并把示例日期改成实际发布日之后的日期。已有句子的 `id`、`text`、`availableFrom` 保持不变；调整 JSON 中的排列顺序不影响结果。删除旧句子、修改旧内容或把新句子的日期填到今天或过去，可能改变既有结果。本次从旧算法迁移到按 ID 排序，可能改变升级当天的原选择；上述稳定性保证从这版算法开始。缺失或非法的起始日期、重复 ID 会直接使构建失败。

文案会随静态站点发布到浏览器，请将准备公开的内容放在这个文件中。

## GitHub Pages 发布

本仓库对应的默认站点配置是 `https://jockiepeng.github.io/my-universe/`；该配置不代表已经上线。

1. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
2. 将代码提交到 `main`，或者在 `main` 上手动运行 **Check and publish blog** 工作流。
3. 工作流自动测试、检查、构建、生成搜索索引并发布。PR 只检查，不发布。

项目路径会从仓库名称推导，`*.github.io` 用户站点使用根路径。自定义域名时，在仓库 Actions **Variables** 设置 `SITE_URL`（例如 `https://blog.example.com`）和 `BASE_PATH`（根路径填 `/`），并在 Pages 中绑定域名。需要 CNAME 时可放入 `public/CNAME`。

本地可通过环境变量 `SITE_URL`、`BASE_PATH` 覆盖构建地址。配置默认仍为本仓库的项目站点。

## 开启评论

1. 在公开仓库中开启 **Discussions**。

## 阅读量

文章详情显示“阅读 — 次”，导航显示“博客累计浏览量 — 次”；正式站点从 [不蒜子](https://busuanzi.ibruce.info/) 获取页面与全站累计浏览次数，收到数字后才替换占位。这里统计的是 PV，不是人数；刷新和重复打开可能再次计数。首页、文章、归档、关于和游戏等页面都参与统计并在导航中显示全站数字。

只有 HTTPS 且地址匹配构建时的正式域名，才会加载计数。第三方服务不可用时保留占位，文章仍能阅读。发布后需要验证服务在实际域名上的可用性。

重新打包、部署不会重置服务端计数；完整流程、地址变更的影响和维护注意事项见[重新打包、部署会改变阅读量吗？](#重新打包部署会改变阅读量吗)。

全站数字使用不蒜子的 `site_pv`，并非相加当前文章的 PV。站点归属由第三方决定，通常按主机识别；GitHub Pages 同一主机下的其他项目若也使用该服务，可能共享全站计数，项目子路径不保证隔离。新接入页面未曾上报的历史访问不会被补齐，因此该数字不能称为从建站第一天起的精确总量；需要严格按项目隔离或独立备份时应换用自有统计服务。

## 导航访客归属地

固定导航右侧同一行显示「定位图标 + 归属地」和「博客累计浏览量」，各页面均可见；窄屏导航与操作按钮收进菜单，定位和计数仍在右侧，过长地区省略显示但保留完整文字；屏幕阅读器仍可识别“IP 归属地”。归属地由浏览器每页请求一次 [ipapi.co](https://ipapi.co/json/) 的 HTTPS JSON 接口取得，不需要密钥或自建服务器；本地开发和预览不查询。接口已检查返回成功及允许正式站点跨域访问；国家名由浏览器转为中文，省市沿用接口返回名称，可能为英文。归属地只有国家信息时显示国家即可，重复地区名只展示一次。

显示的是当前网络出口 IP 的大致归属地，不使用设备 GPS，不请求精确位置权限，不展示或持久保存原始 IP，也不创建访客明细后台。定位服务为完成查询仍会接收请求者的出口 IP；请求省略凭证与页面 Referer。代理、移动网络和 IP 数据库更新都可能影响结果。

接口 8 秒无结果、被拦截、返回错误或达到免费配额时显示「暂不可用」，不伪造位置、不自动重复请求；浏览量统计独立加载。无 JavaScript 时保留计数占位并提示归属地需要 JavaScript。公开接口可用性及配额由提供方决定，高访问量时可考虑更换带服务承诺的接口。

构建后运行 `npm run test:visitors`，以本地产物模拟正式来源，拦截定位响应与统计 JSONP 请求，验证成功、错误、超时、迟到响应、每页单次计数及手机显示，不增加真实计数。测试会下载公开的不蒜子脚本本身，需要网络；截图保存在 `.tools/screenshots/visitor-info-*.png`。

## 动态页面

`/moments/` 使用一条专用 GitHub Discussion 保存动态。站长在页面下方使用 giscus 发表顶级评论，卡片仅展示配置的 GitHub 用户发表的顶级评论；访客可以在同一页面的讨论区回复对应评论。每张卡片也有该条评论的 GitHub 直达链接。giscus 的评论区本身仍会展示其他参与者发表的顶级评论；卡片跳转到页面讨论区时不会自动定位具体评论。

启用步骤：

1. 在公开的 giscus 仓库中启用 Discussions，并安装 giscus GitHub App；按照下方评论配置设置仓库、分类和 ID。
2. 在该仓库的评论分类中新建一条专用 Discussion，记下 URL 最后的数字。不要将该 Discussion 用于文章评论。
3. 默认使用 Discussion 6；若更换讨论，在仓库 Actions Variables 设置 `MOMENTS_DISCUSSION_NUMBER` 为新编号；可选设置 `MOMENTS_AUTHOR` 为站长 GitHub 用户名，默认使用仓库所有者。动态 Discussion 必须位于 `PUBLIC_GISCUS_REPO` 配置的仓库中；如果使用其他仓库，默认 `GITHUB_TOKEN` 可能无权读取，请确保其读取权限。
4. 运行一次 Pages workflow。此后工作流每 5 分钟尝试同步并部署，GitHub 调度可能延迟；不需要手动提交动态。每次成功的快照缓存在 Actions，API 失败时恢复最近的缓存；缓存可能因 GitHub 的保留策略被清理。首次成功同步之前没有可恢复的数据。

动态内容由 GitHub 渲染为 HTML 后生成到静态站点。任何有权编辑站长评论的人都能够影响页面内容；请仅使用可信的仓库与账号。动态不加入构建时文章 RSS。关闭 Actions 或 GitHub 不可用时，站点保留上一次部署的数据。
如果同步日志提示无权读取 Discussion，请创建具有目标仓库 Discussions 读取权限的令牌，并将它保存到 Actions Secrets 的 `MOMENTS_TOKEN`；不要把令牌放入 Actions Variables 或页面代码。

动态 Discussion 中站长新增、编辑或删除评论时，`discussion_comment` 事件也会触发构建，无需等待定时调度；其他讨论不会触发构建；该讨论中的访客回复也会触发同步。事件触发要求动态 Discussion 和本工作流位于同一仓库。五分钟定时任务保留作为兜底，但 GitHub 的调度可能延迟或跳过。

动态列表每页显示 20 条。浏览器首次只加载第一页；切换页面、搜索或按北京时间筛选发布日期时，按需下载构建生成的搜索索引与对应数据分片。关键词匹配动态正文及回复，筛选后重新分页。索引和已请求的分片在当前页面中复用；加载失败可通过重新筛选或翻页重试。关闭 JavaScript 时可阅读第一页。同步仍然会从 GitHub 全量分页读取，因此数据量大时同步与构建耗时会增长；编辑和删除会在下一次成功同步后反映到索引中。

## 功能更新记录规则

功能更新页面的数据维护在 `src/data/changelog.json`，按提交日期倒序记录，并同时填写中文和英文。新增记录应包含可展开的 `details` 数组，每一项填写中文标题 `title`、英文标题 `enTitle`、中文说明 `text` 和英文说明 `en`：

- 新增功能：说明功能内容和使用方式，并说明技术原理。
- 修复问题：分别说明原来的问题、处理方式、更新后的效果和技术原理。
- 优化功能：分别说明原来的情况、优化方式、更新后的效果和技术原理。
- 删除功能：说明删除内容、原因和对使用的影响，并在适用时说明技术原理。

技术说明应以实际实现为依据，明确外部依赖、同步延迟等会影响使用的限制；历史记录不强制补写。`details` 标题可使用「原来的情况」「处理方式」「更新后的效果」「功能内容」「技术原理」。仅有摘要的旧记录保持原样，不显示展开按钮。
