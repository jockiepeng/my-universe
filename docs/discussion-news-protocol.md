# 每日新闻推送协议 v1.1

## 上游如何推送

上游为 `my_cron` 仓库的 `daily-news-blog` 定时任务。

通过 GitHub API，向博客仓库 `jockiepeng/my-universe` 的新闻专用 Discussion 发布顶级评论。**一天一条评论，包含当天整份日报**；所有日期共用这条 Discussion。

## 推送时间

每天北京时间 **08:40（Asia/Shanghai）** 推送当天日报。

如果届时当天日报尚未生成，则在生成完成后补推当天内容。不会将昨天的内容当作今天日报推送。

## 推送内容

- 日报日期。
- 每篇新闻的标题、中文摘要、阅读理由、来源、摘要依据和原文链接。
- “历史上的今天”的事件日期、标题、摘要和来源链接。

评论仅包含以上阅读内容，不附带运行说明、机器可读新闻数据、JSON 代码块或本地长图文件。

## 推送格式

每条评论使用 **Markdown 日报正文**，格式如下。新闻与历史事件按当天实际条目依次列出。

```markdown
# 2026-11-12 每日新闻

## 1. 新闻标题

**摘要：** 新闻的中文概括。

**阅读价值：** 推荐阅读的理由。

**来源：** 来源媒体名称。

**摘要依据：** 原文 / RSS 摘要（未读取完整正文）

[阅读原文](https://example.org/news)

## 2. 新闻标题

……

## 历史上的今天

### 1918-11-12 · 事件标题

事件的中文概括。

[事件来源](https://example.org/history)
```

示例中的日期、标题、正文与链接均为占位；历史事件的月日与实际日报日期一致。没有历史事件时省略该部分。

## 稳定格式与更新规则

- **日期与结构**：首个非空行为 `# YYYY-MM-DD 每日新闻`，日期按北京时间确定；新闻标题固定为 `## N. 新闻标题`，从 1 连续编号。字段标识固定使用示例中的“摘要”“阅读价值”“来源”“摘要依据”和“阅读原文”，保留对应加粗标记与链接格式，不随意改名或调整标题层级。
- **内容边界**：标题、来源与摘要依据各占一行；摘要和阅读价值可包含多段文字，但不使用与协议相同的章节标题或字段标识来表示正文。原文与事件来源链接必须是 HTTP(S) 地址。
- **摘要依据**：按实际情况填写 `原文` 或 `RSS 摘要（未读取完整正文）`，不把仅阅读摘要表述为读取完整正文。
- **历史事件**：固定章节名为 `## 历史上的今天`，每项标题为 `### YYYY-MM-DD · 事件标题`，随后为摘要和 `[事件来源](URL)`。事件年份早于日报年份，月日与日报日期一致；没有有效历史事件时省略整个章节。
- **数量**：新闻目标为 10 条，历史事件目标为 3 条；可信内容不足时允许少于目标数量，不拼凑、不补造。上游若提供更多历史事件，下游接收完整内容，页面默认展示前 3 条。没有有效新闻时不发布空日报。下游按实际条数展示，不推测不足原因。
- **同日修订**：同一日期只维护一条顶级评论；补推或修订时更新该评论，不重复新增。日报所属日期以标题为准，不以评论创建或编辑时间代替。
- **格式变更**：以上格式是 v1.1 的读取约定，改变日期格式、字段名称或标题层级前，先协调上下游并更新协议版本。评论无需额外携带机器版本标记。

## 下游接入约定与待办（my-universe）

- **同步与部署**：从 Discussion #9 分页读取 `jockiepeng` 发布的顶级评论，按本协议解析原始 Markdown 正文。复用动态的 Actions 快照方案，接入评论新增、编辑、删除事件和定时同步兜底，再构建部署；浏览器只读取站内快照，不直接访问 GitHub API 或持有 Token。
- **校验与更新**：校验日报日期、稳定结构、必要字段和链接；按“Discussion 编号＋日报日期”识别日报，依据评论内容识别修订，不再依赖 v1.0 的 JSON、`id` 或 `source_sha256`。同日重复、格式不符等异常须报告，不盲目拼接或覆盖有效数据；同步失败保留上次有效快照，成功完整同步时反映评论删除。
- **专区展示**：默认展示最新日报，支持按日期浏览历史；展示新闻标题、简介、新闻价值、来源、摘要依据与原文链接，以及历史事件。内容安全渲染，显示实际条数、日报日期和下游同步时间；区分今日未发布、无历史事件与加载失败。不补造已从协议移除的生成时间、运行说明等字段。
- **未读通知**：按北京时间检查今天、昨天、前天的日报，每天一条未读通知，与规划通知共用入口。仅打开通知弹窗不清除新闻未读；进入对应日报后，成功展示有效内容才标记该日已读。同日修订不重新提醒，状态保存在当前浏览器，暂不跨设备同步。
- **发布验收**：覆盖 Markdown 解析、修订去重、异常保留、删除、日期边界和已读规则；检查新闻页、历史浏览、来源链接、手机布局及通知，并按仓库要求补齐双语更新记录、Review 与发布验证。

### 边界与当前状态

本文件为上下游接入约定。下游已实现新闻专区、Actions 快照同步及近三天未读通知；首次真实数据仍需成功同步和部署后显示。08:40 是上游推送时间，网站显示还需等待 Actions 同步、构建与部署。上游负责新闻采集及事实核查，下游格式校验不代表独立验证新闻真实性。
