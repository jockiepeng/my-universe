## 共用技术与结构

站点使用 **Astro 生成静态页面，TypeScript 处理浏览器交互，JavaScript 规则模块计算游戏状态**。访问游戏页后，计算在访客浏览器中完成；当前版本没有游戏账户或服务端排行榜。

| 层次 | 使用的技术 | 职责与代码位置 |
| --- | --- | --- |
| 页面与路由 | Astro、HTML | `src/pages/games/` 提供各游戏页面；`src/lib/games.ts` 管理大厅目录 |
| 规则计算 | JavaScript `.mjs` | `src/lib/` 中的游戏模块计算移动、随机布局、碰撞、胜负与分数，独立于页面元素 |
| 操作与流程 | TypeScript、浏览器事件 | `src/scripts/` 把键盘、点按、滑动转换成动作，调度计时、调用规则并更新画面 |
| 连续绘制 | Canvas 2D | 贪吃蛇、打砖块将坐标状态画到画布上 |
| 格子与离散结果 | DOM、CSS Grid、CSS | 扫雷、连连看、2048、骰子使用页面元素展示格子或点数 |
| 反馈动效 | CSS、Web Animations API、SVG | 2048 移动星球，骰子摇动，连连看用 SVG 画连接线 |
| 本机记录 | `localStorage`、JSON | 保存金币、棋盘或最佳成绩；范围因游戏而异，详见后文 |
| 自动验证 | Node.js 测试、Playwright | 验证规则函数及真实浏览器中的键盘、触屏、计时与布局 |

一次操作大体经历：

```text
玩家输入 / 定时器到点
        ↓
控制脚本检查：是否已开始、暂停、结束或正在播放反馈
        ↓
规则模块计算：坐标、分数、碰撞、可连接路径或胜负
        ↓
更新游戏状态，按需保存记录
        ↓
Canvas 重画 / DOM 更新 / 播放反馈
```

例如，蛇身是一组坐标，雷区是一组格子数据，小球有位置和速度。画面由这些数据绘制出来。贪吃蛇、2048 的主要移动函数返回新状态；扫雷、连连看、打砖块的规则函数直接更新传入的游戏对象。

四款街机／棋盘游戏共用 [`ArcadeLayout.astro`](../src/layouts/ArcadeLayout.astro) 和 [`arcade.css`](../src/styles/arcade.css)，使用站点已有的深浅主题、返回大厅入口和规则说明。Canvas 使用逻辑坐标，显示尺寸与设备像素比单独处理，缩放不会改变游戏规则。

## 扫雷：布雷、数字与空白展开

代码入口：[`minesweeper.mjs`](../src/lib/minesweeper.mjs)、[`minesweeper.ts`](../src/scripts/minesweeper.ts)。

### 棋盘如何表示？

棋盘在数据中是一个一维数组。第 `r` 行、第 `c` 列对应：

```js
index = r * cols + c;
row = Math.floor(index / cols);
col = index % cols;
```

坐标从 0 开始。每个格子记录四件事：

```js
{ mine: false, adjacent: 0, revealed: false, flagged: false }
// 是否有雷、周围雷数、是否翻开、是否插旗
```

当前难度为：

| 难度 | 棋盘 | 地雷数 |
| --- | --- | --- |
| 简单 | 9×9 | 10 |
| 中等 | 12×12 | 22 |
| 困难 | 16×16 | 40 |

### 雷区如何随机生成？为什么第一下安全？

**地雷在第一次有效翻开格子时才生成。** 新游戏初始状态是 `ready`，所有格子的雷信息尚未确定。插旗、点击已插旗的格子都不会触发布雷。

第一次有效翻格时，`revealCell()` 按以下顺序执行：

1. 找出点击格和它周围八格中仍在棋盘内的格子，建立安全集合。
2. 把安全集合之外的格子收集为候选位置。
3. 使用 **Fisher–Yates 洗牌**打乱候选位置：从数组末尾往前，每次随机选择 `0～i` 之间的位置，与第 `i` 项交换。
4. 取打乱后的前 `mineCount` 个位置放雷，保证雷数固定、位置不重复。
5. 计算每个格子的邻雷数，进入 `playing` 状态。之后地雷位置固定。

例如，在简单模式中心点第一次点击时，点击格与周围八格共 9 格被排除，剩余 `81 - 9 = 72` 格中放置 10 颗雷。在边缘或角落，安全集合只包含棋盘内实际存在的邻格。

这里默认使用 `Math.random()`。测试时可以传入受控的随机函数，使雷区可重复，便于检查首击安全等规则。

### 每个数字如何计算？

`neighbors()` 枚举行列偏移 `dr, dc ∈ {-1, 0, 1}`，排除 `(0,0)` 和越界位置。数一数这些邻格中有多少 `mine === true`，就是格子的 `adjacent`。

```text
✹  ·  ·
·  2  ·
·  ·  ✹
```

中间格周围八格共有两颗雷，所以显示 `2`。斜对角也参与计数。数字 `0` 在界面上显示为空白。

### 为什么第一次会翻开一大片空白？

这个效果由 **安全区域与洪水填充（flood fill）**共同产生。

点击格周围没有雷，因此点击格的数字一定为 0。翻开一个 0 格后，程序自动检查它的邻格；遇到另一个 0 格，就继续向外展开；遇到数字大于 0 的安全格，就显示数字，并在这一方向停止展开。

当前实现用数组作为待处理栈，执行 `pop()`，属于**迭代式深度优先遍历**：

```text
将点击格放入待处理栈
只要栈不为空：
    取出一个格子
    若它已经翻开、已插旗或是地雷，跳过
    翻开该格
    若邻雷数为 0，将其邻格加入栈
```

因此一次点击会显示：**与起点相连的 0 区域，加上包围这片区域的数字边界**。已经翻开的格子不会重复展开，插旗格会保留。

展开面积取决于实际雷区，可能较大，也可能较小。首击安全保证点击格及周围一圈没有雷；当前版本没有“整盘无猜测可解”的布局筛选算法。

### 怎样判断获胜？

判定条件为：每个格子要么是雷，要么已经翻开，即 `cells.every(cell => cell.mine || cell.revealed)`。不要求把每颗雷都插旗，旗帜只是玩家的标记。页面上的“剩余雷数”是总雷数减插旗数，并不表示程序验证了旗帜正确。

## 贪吃蛇：移动、食物与增长

代码入口：[`snake.mjs`](../src/lib/snake.mjs)、[`snake.ts`](../src/scripts/snake.ts)。

### 蛇身如何表示？

棋盘为 20×20，共 400 格。蛇身是按“头到尾”排列的坐标数组：

```js
snake = [{ x: 5, y: 4 }, { x: 4, y: 4 }, { x: 3, y: 4 }];
// 第一项是头，最后一项是尾，当前长度为 3
```

新游戏中蛇长 3 格，位于棋盘中央，朝右前进。方向对应一个移动向量：上 `(0,-1)`、下 `(0,1)`、左 `(-1,0)`、右 `(1,0)`。

### 速度如何控制？

蛇每次逻辑更新前进 **一格**。控制脚本用 `setTimeout()` 调度下一步，间隔决定速度：

| 档位 | 目标间隔 | 理论移动速度 |
| --- | --- | --- |
| 漫游 | 160 毫秒／格 | 约 6.25 格／秒 |
| 巡航 | 120 毫秒／格 | 约 8.33 格／秒 |
| 跃迁 | 85 毫秒／格 | 约 11.76 格／秒 |

浏览器繁忙时回调可能晚于目标时间执行，因此这些是目标速度。当前版本吃到食物不会自动加速；切换速度会开始新一局，并读取这一档的最高分。

一次更新先计算新头坐标：

```js
newHead = { x: oldHead.x + dx, y: oldHead.y + dy };
```

随后检查碰撞、更新蛇身和分数，再重画 Canvas，并安排下一次更新。逻辑按格子移动；页面大小和显示器刷新率不会改变每一步跨越的格数。

### 食物如何随机出现？

`placeFood()` 先将所有蛇身位置放入集合，再扫描棋盘，把未被蛇占用的格子收集为 `empty`：

```js
food = empty[Math.floor(Math.random() * empty.length)];
```

在随机源近似均匀的前提下，每个空格被选中的机会相同。初始蛇长 3 格，食物从其余 397 格中选择。食物生成后保留原位置，直到被吃掉；随后从更新后的空格集合中选择下一颗。

这种做法扫描一次棋盘就能找到位置，盘面接近填满时也不需要反复随机试错。没有空格时返回 `null`，游戏判定满盘获胜。

### 尾巴如何变长？

**每一步都在数组开头加入新头；普通移动删除旧尾，吃到食物时保留旧尾。**

以上面的三格蛇向右移动为例：

```text
原来：      [(5,4), (4,4), (3,4)]

普通移动：  [(6,4), (5,4), (4,4)]
            加入新头 (6,4)，移除旧尾 (3,4)，长度仍是 3

吃到食物：  [(6,4), (5,4), (4,4), (3,4)]
            加入新头 (6,4)，保留旧尾 (3,4)，长度变成 4
```

因此，增长来自这一步少删一个尾格。每颗食物加 10 分、增长一格，然后生成下一颗食物。

### 如何防止掉头和快速按键导致自撞？

`queueDirection()` 最多保存两个待执行转向，每步取一个。新方向与最后一个已接受的方向比较，重复方向和反方向会被忽略。

例如正向右走时，快速按“上、左”，会先向上走一格，再向左走一格。它们分两步执行，避免同一步内直接从右变成左。新头越界或撞到身体时结束。

碰撞检查还处理了尾格的特殊情况：**没有吃到食物时，本步旧尾会离开，允许新头进入这个正在腾出的尾格。** 吃到食物时尾格保留，按完整蛇身检查碰撞。

### 暂停时为什么不会继续走？

暂停会清除当前定时器，并用 `performance.now()` 保存距下一步还剩多少时间。假设巡航一格需 120 毫秒，已经过去 50 毫秒时暂停，恢复后会再等待约 70 毫秒。

新一局也先清除旧定时器，始终只安排一个后续更新，避免多次点击开始后同时跑多个循环。切换窗口或离开页面会暂停，回到页面后手动继续。

## 打砖块：时间、速度与碰撞

代码入口：[`breakout.mjs`](../src/lib/breakout.mjs)、[`breakout.ts`](../src/scripts/breakout.ts)。

### 小球如何移动？

游戏使用 720×560 的逻辑坐标。小球记录圆心 `(x,y)`、半径 `r=7`、水平速度 `vx` 和竖直速度 `vy`；挡板、砖块记录矩形位置和尺寸。

画面由 `requestAnimationFrame()` 驱动。两帧之间的时间差换算成秒，再计算：

```js
x += vx * dt;
y += vy * dt;
```

速度的单位是逻辑像素／秒。显示成手机上的小画布时，仍使用相同逻辑坐标，再统一缩放绘制。鼠标和手指的位置也按画布宽度比例换算回逻辑坐标。

第一关球速为 320；初次发球的水平分量为 `320 * 0.28`，竖直分量向上，按 `-Math.sqrt(speed ** 2 - vx ** 2)` 计算，保持总速度为 `speed`。当前发球方向由公式确定，没有随机抽取角度。

### 如何计算碰撞和反弹？

| 碰到的位置 | 处理方式 |
| --- | --- |
| 左右墙 | 把球推回合法边界，让水平速度朝向场内 |
| 顶部 | 把球推回边界，让竖直速度朝下 |
| 挡板上表面 | 球必须正在下降、上一小步还在挡板上方，并在这一小步跨到上表面，才触发反弹 |
| 砖块 | 检查圆与矩形是否接触，根据进入方向或重叠深度决定水平／竖直反弹，移除砖块并加 10 分 |

圆与矩形的接触通过**矩形上离球心最近的点**判断。将球心坐标限制在矩形边界内得到 `(nearestX, nearestY)`；如果球心到这个点的距离平方不大于 `r²`，就发生接触。

砖块用 `alive` 标记是否仍存在，只检查活着的砖块；命中后立即设为 `false`，防止同一块反复得分。球碰撞后还会被推到接触面的外侧，降低下一步仍重叠造成的重复反弹。

### 为什么挡板边缘能改变方向？

计算球落点与挡板中心的偏移，将其归一化到 `[-1,1]`：

```js
offset = (ball.x - paddleCenterX) / (paddle.width / 2);
angle = offset * Math.PI / 3;
vx = speed * Math.sin(angle);
vy = -speed * Math.cos(angle);
```

中央落点对应接近竖直向上；越靠左，水平速度越朝左；越靠右，水平速度越朝右。最大偏转为相对竖直方向约 60°。

### 球速高时，如何避免穿过砖块？

单帧一次移动太远，可能跨过整个砖块而漏掉接触。当前物理计算会把一帧切成多个更小的子步，每个子步都检查碰撞：

```js
substep = Math.min(remaining, 1 / 240, radius * 0.45 / speedNow);
```

它同时限制子步时间和移动距离。控制脚本将每帧时间差限制到 0.05 秒以内，规则函数也将单次输入限制到 0.1 秒以内，避免页面卡顿后一次跳跃过远；代价是严重卡顿时游戏时间会放慢。

### 生命和关卡如何变化？

每局 3 条生命。球完全落出底部时扣一条，然后停在挡板上等待再次发球；不会在等待期间重复扣命。生命归零进入结束状态。

清空砖块后等待玩家进入下一关，分数与剩余生命保留。砖块为 9 列，行数从 5 增至最多 7；球速按 `min(760, 320 + (level - 1) * 42)` 增加，挡板宽度按 `max(78, 110 - (level - 1) * 4)` 缩小。

## 连连看：两次转弯与洗牌

代码入口：[`link-game.mjs`](../src/lib/link-game.mjs)、[`link-game.ts`](../src/scripts/link-game.ts)。

### 图案怎样生成？

简单棋盘为 6 行×6 列，180 秒；普通棋盘为 8 行×6 列，240 秒。数据用 `0～7` 表示八种图案，`null` 表示已消除的空格，数字 `0` 也是有效图案。

先成对加入图案，再使用 Fisher–Yates 打乱，所以每种图案的数量始终为偶数。每次只消除相同图案的一对，剩余数量也保持成对。

### 如何判断两格能否用两次转弯连接？

`findPath()` 使用带方向和转弯次数的**广度优先搜索**。搜索状态包含：

```text
当前行列 + 进入方向 + 已转弯次数 + 路径拐点
```

从起点向上下左右尝试前进：第一次选择方向不算转弯；之后改变方向，转弯数加 1；超过 2 就放弃。可经过空格和目标格，不能穿过其他未消除图案。

记录已搜索状态时，键包含“行、列、方向”，同时保存到这里所用的较少转弯数。相同位置、相同进入方向，如果已有用更少或相同转弯数到达的路线，就跳过新路线。方向必须参与记录，因为从左进入和从上进入，后续可用的转弯余量可能不同。

只要找到满足规则的路线就接受；当前搜索不承诺展示所有合法路线或最少转弯的路线。渲染时将同方向上的连续点压缩为线段端点，用 SVG 折线短暂展示。

### 连线为什么可以绕到棋盘外面？

算法在棋盘四周虚拟增加一圈空白。允许的行坐标是 `-1～rows`，列坐标是 `-1～cols`，原棋盘仍是 `0～rows-1`、`0～cols-1`。

这圈空白供路径经过，因此两个上边缘的相同图案可以先向上、再横向、最后向下，形成两次转弯。外围只扩一圈，搜索区域有限。

### 提示和洗牌如何保证有用？

提示通过 `findPair()` 遍历相同图案的候选对，再调用实际的路径算法寻找可消的一对，因此提示同样遵守阻挡和转弯规则。

洗牌只打乱未消除的图案，保留所有空洞、图案种类与数量。随机排列完成后检查有没有合法配对；如果仍是死局，就先寻找一对几何上可连接的位置，再通过交换，把某个图案的另一份移到对应位置，保证至少有一对能消。

初始局面、洗牌后的局面都检查可玩性；消除后的剩余局面若出现死局，会自动免费洗牌。每局手动提示、手动洗牌各 3 次。当前保证“有可走的一步”，不保证不使用后续洗牌就能一路清盘。

### 计分、暂停与键盘怎样处理？

每对加 100 分，全部消除后按剩余完整秒数每秒奖励 10 分。最高分在成功配对后就更新，通关时再计入时间奖励。配对反馈约 400 毫秒，期间锁定下一次选择，防止重复消除。

倒计时使用实际经过的毫秒数；暂停停止扣时，并遮住棋盘、阻止操作。空洞较多时，键盘先沿指定行列寻找下一个图案，找不到则按阅读顺序回绕，确保零散的最后几格仍能到达。

## 2048：压缩、合并与随机生成

代码入口：[`planet-2048.mjs`](../src/lib/planet-2048.mjs)、[`planet-2048.ts`](../src/scripts/planet-2048.ts)、[`PlanetOrb.astro`](../src/components/PlanetOrb.astro)。

### 一次滑动如何计算？

4×4 棋盘存为长度 16 的数组，`0` 表示空格。每次移动按目标方向依次读取每行或每列，对每条线执行：

1. 去掉空格，把数字压到一起。
2. 从靠近移动方向的一端扫描，相邻数字相同就合成两倍数值。
3. 这两个输入数字被一起消费，新合成数字在同一回合不再合并。
4. 剩余位置补 0，再写回棋盘。

```text
向左： [2, 0, 2, 4] → [4, 4, 0, 0]，本步得 4 分
向左： [2, 2, 2, 2] → [4, 4, 0, 0]，本步得 8 分
向左： [2, 2, 4, 0] → [4, 4, 0, 0]，本步得 4 分
```

最后一例中的新 `4` 等到下一回合才可以和另一个 `4` 合并。向右、向上、向下复用同样的处理过程，改变读取和写回的索引顺序。

### 新数字怎样出现？什么时候结束？

新游戏在两个不同空格生成数字。每次**棋盘确实发生变化的移动**后，从剩余空格中随机选一个位置，再以约 90% 概率生成 2、10% 概率生成 4，默认使用 `Math.random()`。

无效移动不会生成新数字、增加步数或改变分数。得分为本次所有合并产生的数值之和。达到 2048 时显示胜利，玩家可以选择继续；棋盘无空格且横向、纵向都没有可合并的相邻数字时结束。

### 星球和移动动画怎样实现？

规则模块返回新棋盘，同时返回每个数字从哪里移到哪里，以及哪些格子刚刚合并。控制脚本通过 Web Animations API 播放约 130 毫秒位移动画，再更新显示；星球外观由 HTML 元素与 CSS 绘制。

游戏先计算并保存新状态，再播放动画。动画期间用 `busy` 防止重复提交移动；关闭动态或系统要求减少动态时，直接显示计算结果。恢复存档会校验版本、棋盘尺寸、合法数字和分数等字段。

## 猜骰子：随机、赔率与结算

代码入口：[`dice-game.mjs`](../src/lib/dice-game.mjs)、[`dice-game.ts`](../src/scripts/dice-game.ts)、[`DiceFace.astro`](../src/components/DiceFace.astro)。

### 骰子如何随机生成？

每颗骰子调用 `crypto.getRandomValues()` 获取 `0～255` 的随机整数：遇到 `252～255` 就丢弃并重取，其余执行 `value % 6 + 1`，分别生成三颗骰子。

原因是 252 能被 6 整除，`0～251` 中每个余数恰好出现 42 次，能避免直接对 256 种结果取余带来的偏差。浏览器接口提供密码学安全的伪随机，通常由操作系统熵源支撑；这里没有接入物理真随机设备。

每种三骰组合的目标概率为 `1/216`；**总点数并不等概率**，例如 10、11 点各有 27 种组合，3、18 点各只有 1 种。骰子生成过程不参考下注、金币或历史频率。

### 大小、豹子和总点数怎样判断？

总点数为三颗之和。普通小为 4～10，大为 11～17；三颗相同为豹子，大小下注都输。押总点数只比较总和，豹子仍可命中对应总点数。

历史显示点数对应的“小／大”，并额外标记豹子；豹子的大小标签不代表大小下注能赢。统计中的小、大、豹子分别计数，豹子单独归类。

| 押注位置 | 净赢倍数 |
| --- | --- |
| 大、小 | 1 |
| 4、17 点 | 50 |
| 5、16 点 | 18 |
| 6、15 点 | 14 |
| 7、14 点 | 12 |
| 8、13 点 | 8 |
| 9、10、11、12 点 | 6 |

3、18 点会记录，但没有总点数下注位置。各地骰宝赔率表可能不同，这里使用上表中的固定规则。

### 金币如何结算？

净赔率为 `m` 时，押注 `b` 并命中会返还 `b * (m + 1)`，其中包含本金。所有位置分别算返还，再统一计算：

```text
本局净盈亏 = 总返还 - 总下注
新余额     = 旧余额 - 总下注 + 总返还
```

例如在“小”押 10 金币，命中后返还 20，净赚 10。一局可以押多个位置；只要总下注不超过余额且金额是合法正整数，就分别判定。整局净赚才计入“盈利局数”。

开骰时先生成结果、完成结算并保存，再播放约 650 毫秒摇动反馈。忙碌标记阻止重复点击；支持 Web Locks 的浏览器会串行处理同源标签页的结算写入，并在写入前检查是否有较新的存档。页面也监听 `storage` 事件同步其他标签页的进度。

恢复存档时，从初始金币逐局重新计算，核对下注、返还和余额是否一致。历史总点数按 3～18 累计频次，取最高频次数并保留所有并列点数。

## 存储、暂停与验证

### 六款游戏保存什么？

| 游戏 | 保存内容 | 刷新后的行为 |
| --- | --- | --- |
| 猜骰子 | 初始金币、余额、全部已结算回合 | 恢复金币、历史和统计；待下注筹码不保存 |
| 2048 | 棋盘、分数、最高分、步数、是否已选择继续 | 恢复当前局面 |
| 贪吃蛇 | 各速度档最高分 | 开始新局；不恢复蛇身和食物位置 |
| 扫雷 | 各难度最快通关时间 | 开始新局；不恢复雷区和本局用时 |
| 打砖块 | 最高分 | 回到第一关、3 条生命；不恢复小球状态 |
| 连连看 | 最高分 | 开始新局；不恢复图案和倒计时 |

这些数据保存在 `localStorage`，归属于当前浏览器的站点来源，来源由协议、域名和端口组成。相同来源下重新打包不会清空已有记录；清除站点数据、换浏览器或换来源后，不会自动带来原记录。存储失败时页面提示，当前页仍可继续游玩。

这与文章阅读量使用不蒜子服务端存储的机制不同。当前游戏记录可由浏览器使用者检查或修改，适用于本机娱乐，没有服务端防作弊或跨设备同步。

### 计时为什么使用实际时间差？

扫雷和连连看约每 200 毫秒刷新一次计时，但实际累计的是 `performance.now()` 的时间差。计时器回调可能因浏览器调度延迟，因此按时间差计算能比“每次回调固定加一秒”更准确。

扫雷累计有效游戏时间，界面显示向下取整的秒数，通关纪录向上取整且至少为 1 秒；连连看扣除有效时间，界面显示向上取整的剩余秒数。暂停、后台和窗口失焦时冻结计时，恢复时重置参考时刻，避免把暂停时长补扣回来。暂停期间也遮盖棋盘并阻止操作。

贪吃蛇清除步进定时器，打砖块停止动画循环；恢复都需要明确操作。2048、骰子按玩家动作更新，无持续运行的游戏倒计时。

### 手机手势和画布缩放怎样处理？

Pointer Events 将鼠标和手指操作统一为按下、移动、松开和取消事件。滑动方向比较水平和垂直位移，取位移较大的轴；移动不足阈值则视为未滑动。画布使用 `touch-action` 管理手势，避免游戏操作同时滚动页面。

Canvas 的内部像素尺寸根据显示宽度和设备像素比调整，当前最多使用 3 倍像素比；绘制时再映射回固定逻辑坐标。这样高分屏上更清晰，规则坐标保持不变。

贪吃蛇和打砖块的主要按钮通过 [`arcade-input.ts`](../src/lib/arcade-input.ts) 处理触屏短按：松手位置仍在按钮内且移动不超过 12 像素时执行，滑出或取消则不执行；同时抑制同次触摸随后产生的兼容点击，避免操作两次。键盘激活保留正常行为。
