# Dice game implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 首页进入游戏大厅，持续游玩三骰猜大小，保存金币、历史和点数统计。

**Architecture:** Astro routes use BaseLayout; an isolated pure game module owns validation and settlement; TypeScript manages DOM and localStorage. No new dependencies or backend.

**Tech Stack:** Astro 7, TypeScript, Node test runner, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-02-dice-game-design.md`

## Global constraints

- Preserve `/my-universe/` base path and existing blog behavior.
- Virtual integer coins only; initial balance defaults to 1,000; configurable 1–1,000,000.
- Triple loses on big/small; total bets use published net odds; history survives refresh and reset clears everything.

## Review focus

- Exhaust all 216 dice outcomes to check classification and total payouts.
- Reject fractions, negative values, insufficient balance and unsafe arithmetic before mutation.
- Restore corrupted storage without crashing and reject internally inconsistent history.
- Prevent duplicate submissions, refresh rollback and overwrites from stale tabs.
- Check mobile overflow, light/dark theme, keyboard dialog, reduced motion and reset persistence.

## Task 1: Rules and state

Files: `src/lib/dice-game.mjs`, `tests/dice-game.test.mjs`.

Interfaces: `createGame(initialCoins)`, `playRound(state, bets, dice)`, `getOutcome(dice)`, `getStatistics(state)`, `restoreGame(raw)`, `rollDice()`; immutable serializable state contains version, initialCoins, balance and chronological rounds. Each round stores dice, bets, stake, payout, net, balance and sequential id.
