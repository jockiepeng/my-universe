# Planet 2048 Implementation Plan

> **For agentic workers:** Execute inline with superpowers:executing-plans, using tests before implementation.

**Goal:** Add a playable, persistent classic 2048 with planet visuals to the existing games lobby.

**Architecture:** A pure `.mjs` game engine owns moves, spawning, scores and save validation. Astro renders the accessible shell and CSS planet artwork; a TypeScript controller handles input and persistence.

**Tech Stack:** Existing Astro, TypeScript, CSS, Node test runner and Playwright.

**Spec:** `docs/superpowers/specs/2026-11-02-planet-2048-design.md`

## Global Constraints
- Classic 4×4 rules; spawn only on changed moves; each tile merges once per move.
- No new dependencies or backend. Preserve other work in the current checkout.
- Keep numbers readable and honor reduced motion and existing motion preferences.
- Keyboard and touch support; refresh restores current progress; restart keeps best.

## Review Focus
- Full boards with a possible adjacent merge remain playable.
- Short swipes, cancelled gestures and clicks must not create a move.
- Restart/dialog and editable controls must not trigger board keyboard actions.
- Unavailable or malformed storage must not prevent playing.
- A winning board restored after refresh must preserve continue behavior.
