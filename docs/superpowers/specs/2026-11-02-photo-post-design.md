# 微信贴图展示方式

状态：用户已确认方案，并补充要求移除短记类型。

最新调整（以此为准）：用户要求所有文章列表不展示图片，只显示标题和摘要等文字；贴图进入详情后在头部以单张横向滑动方式展示，完整纯文字正文在下方。原先的列表完整图文与图片网格方案被本次要求替代。实现与验证见 `../plans/2026-11-02-photo-carousel.md`。

## 需求

新增一种图文展示方式：顶部集中展示多张图片，下方显示文字，文字正文不允许再插入图片。保留文章类型，移除短记类型。

## 方案比较

- **新增“贴图”类型（推荐）**：与文章、短记并列，图片和正文分开管理，规则明确，可在首页单独筛选。
- **给短记添加图片字段**：改动较少，但会改变现有短记的含义，也不便区分纯文字短记与贴图。
- **给文章添加布局开关**：适合长文章切换排版，但这次更接近独立的图文记录方式。

用户确认采用第一种，同时移除短记，最终只保留文章和贴图。

## 展示

- 首页和详情页都显示完整图文。
- 页面顺序为标题和日期等信息、图片区域、文字正文、标签。
- 默认支持 1–9 张图片：单图保留比例，两张双列，四张 2×2，其余使用最多三列的网格。
- 多图缩略图采用统一比例裁切，点击可查看原图；手机端网格不超出屏幕。
- 文字保留换行，使用纯文字排版；Markdown 图片和 HTML 图片不允许出现在贴图正文中，错误提示应指出对应文稿。
- 首页以“贴图”替换“短记”筛选，归档标明“贴图”。分类、标签、日期、独立链接继续使用现有规则。
- 延续现有字体、配色、分隔线和圆角，不引入新的视觉主题。

## 写作方式

- 使用 `kind: photo` 指定贴图类型。
- 在文章配置的 `images` 数组中按顺序填写图片路径和替代文字。
- 正文只写文字；原有文章的图片规则不变。贴图默认不开启评论，可显式开启。
- 补充写作指南和文稿箱模板；不把示例作为真实内容发布。

## 实现与验证边界

沿用 Astro 静态构建和现有图片处理能力，不新增依赖。验证图片数量、正文图片限制、桌面和手机网格、首页筛选、草稿排除，以及原有文章显示。暂不增加上传后台或图片编辑器。
