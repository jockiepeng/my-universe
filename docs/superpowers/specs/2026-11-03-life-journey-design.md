# 人生旅程：走过的路与未写的故事

## 意图

用户认为第一版日／周格子过于像统计图，期待能意识到时间宝贵的、有创意的体验。本次把人生格子改成带人物和人生阶段的二维旅程，先看过去，再看全貌，最后写下未来的憧憬并生成分享图。

用户于 2026-11-03 回复「好的」，确认本次方案，按推荐的二维绘本角色实现完整体验。上一版的日期计算、日／周自由切换和不上传个人输入的要求继续有效。本文覆盖旧设计中「放大后滚动」的交互。

## 用户明确提出的内容

### 用户后续修订（实现中）

用户指出第一版矢量角色丑，且动画应当是「水平面上有很多格子，人在格子上面一步步走过」，随后明确要求地面包含整个人生，并确认「时间铺路石」方向。以此为准：使用独立生成的精细 3D 绘本角色动画图集，固定地面包含全部日／周格子，每格日期和世界坐标不变；一行对应一个生日年，蛇形连接。石片有倒角、接缝、磨痕和足迹，今天以暖金光停驻。提供跟随脚步与完整地面两种镜头，以及暂停／继续。阶段之间镜头拉远快进，阶段内放慢走过相邻的真实格子；到今天后转为完整纵向全景。全屏与分享始终保留完整一生。若已经超过设定寿命，脚步止于设定的最后一天，所有格子完成。

- 婴儿、儿童、少年、青年、成年、中年、老年七个人生阶段。
- 不同时期有不同的小角色，在二维平面上走动。
- 格子先横向展示，再变成纵向展示，之后呈现对未来的憧憬、还可以做些什么。
- 可以分享一张完整人生格子图片，包含已经走过的路程和一句对未来的憧憬。
- 放大查看必须占满屏幕且能一次看到所有格子，替代现在需要拖动查看的方式。

## 整体体验提案

### 开始：输入自己的时间

保留出生日期、预计寿命和日／周切换。未填写时是明确标识的示例；正式演出由有效提交触发，按钮文案可改为「走一遍我的人生」。

### 横向旅程：角色走到今天

提交后进入页面内的宽幅舞台，角色从左向右沿地面走。地面由人生格子构成，已经走过的格子逐渐显色，阶段名和年龄随时间推进。这里的「横向」指舞台布局，不强制手机旋转。

角色属于同一套二维小人风格，通过身形、发型、动作和少量配件表现成长：婴儿爬行、儿童短步、少年与青年较轻快、成年与中年步幅平稳、老年慢步。不用 emoji 顶替角色，也不假定结婚、生子、买房等个人经历。

角色从出生只走到用户的今天，经过的阶段依年龄切换；未来阶段以低对比轮廓和阶段标记呈现，不演成已经发生过的过去。当前属于婴儿或已超过设定寿命，也有完整可用的停止状态。

建议一轮演出约 8–12 秒；支持「跳过演出」与之后的「重播旅程」。短人生或出生当天可更短。减少动态／网站关闭动态时直接展示静态阶段与全貌，所有信息仍可读。

### 转为纵向：一眼看到一生

角色走到今天，画面短暂停留；格子从宽幅布局过渡为纵向的人生全景，保持每格日期与状态一致，不仅旋转图片或设备。已经走过的区域有路程痕迹，今天是明确的停驻点，未来保留空格。

阶段标记与年龄范围沿全景旁排列，便于把格子和真实年龄联系起来。日／周切换保留输入、愿望及今天的位置，不重新强制播放整段演出；可主动重播。

### 未来：选择想做的事，写一句憧憬

格子全景之后是「接下来的路，你想怎么走」。提供少量可选灵感，如「去没去过的地方」「多陪伴在意的人」「学会一件一直想学的事」「照顾好自己的身体」；选择后可修改为自己的话。

提供一行／短段落愿望输入，最多 80 个可见字符。建议默认文案「愿接下来的日子，多一点热爱，也多一点勇敢。」；用户不填写时采用该句，并明确可修改。愿望立即同步至分享预览；通过文本绘制，用户输入不作为 HTML 解析。不保存、不上传。

这一版不增加习惯打卡、账号、愿望数据库或社交发布服务。

## 全屏全貌（替代旧的放大滚动）

- 入口明确叫「全屏看一生」，打开占满视口的查看层；支持时可以进入浏览器原生全屏，不支持时仍然占满网页可用视口。
- 格子根据当前宽高与日／周总数重新排布，整个网格都落在可见区域内；不出现需要拖动的内部大画布，不截掉末尾格子。横竖屏、窗口变化时重新适配。
- 电脑和手机均保留日／周切换、紧凑图例、出生／今天／设定终点、退出按钮。数字、按钮及详情是正常可读大小；格子的大小服从「完整显示」优先。
- 一张手机屏幕展示约三万个日格子时，每格会非常小；全屏扩大的是查看空间，不能同时保证三万格全部大到可逐个触摸。点击查询、方向键与数字格号查询在侧边／底部详情区显示大字，不通过拖动画布寻找。
- 可有一个仅用于查询选中格子附近内容的小预览，但不改变全貌布局；是否需要由实现者根据实际手机可读性决定。
- 打开后焦点进入查看层，Escape／退出关闭并回到原按钮，背景不可操作，关闭恢复原滚动位置。全屏层不带网站导航和悬浮音乐控件。

## 人生阶段（建议的展示分段，非医学定义）

| 阶段 | 年龄（周岁） | 人物表现 |
| --- | --- | --- |
| 婴儿 | 0–2 | 小体型，爬行 |
| 儿童 | 3–11 | 短步行走 |
| 少年 | 12–17 | 身形渐高、轻快走动 |
| 青年 | 18–29 | 直立、较大的步幅 |
| 成年 | 30–44 | 成熟体态、稳定步伐 |
| 中年 | 45–59 | 发型与体态变化、稳步行走 |
| 老年 | 60 起 | 银发、较慢步伐 |

阶段以真实公历生日为边界，继承闰日生日在非闰年采用 2 月 28 日的规则；根据设定寿命截断。周格子跨阶段时以该格起始日期分组，明细仍显示完整日期范围，避免拆分同一个周格。用户低于某阶段年龄时，该阶段只能作为未来显示。

角色采用中性设计，不让性别或职业决定人生路径。角色风格和上述分段属于实现者提案，可在设计确认时调整。

## 分享图片

- 「生成分享图」打开图片预览，用户确认图片效果后可「保存图片」，支持文件分享的设备另有「分享图片」调用系统分享面板。
- 导出独立高分辨率 PNG，不是截取当前屏幕，完整包含所有日／周格子，不能只导出视口内那部分。
- 海报包含：标题、完整格子全景、阶段角色与标记、已走过／尚余格数、今天的停驻点、进度、用户的一句未来憧憬，以及「按设定寿命计算」的简短说明和生成日期。
- 过去的路程以已填色区域／路迹和阶段标记呈现，和格子数据严格对应。长句在海报中自动换行，超长英文及 emoji 也不越界。
- 默认不印完整出生日期；页面提供「在图片中显示出生日期」开关，默认关闭。年龄与天数仍能间接透露年龄，预览以实际导出内容为准。用户主动保存／分享后得到图片文件；不自动发送给任何人。
- 分享面板取消是正常结果，留在预览；不支持文件分享时仍可下载，移动端可通过打开图片后长按保存。重复点击生成不并行创建多份海报；不残留临时对象 URL。
- 示例模式可生成海报，但海报明确标注「示例人生」；不能伪装为填写过的个人结果。

## 视觉提案

让角色与石片构成同一张有空间感的地面，保留网站现有主题背景，舞台与海报共用绘本式角色图集。视觉的主要变化是「脚步留下痕迹、成长、镜头拉远看见一生」这一段连续叙事，周围减少统计卡片。

- 主色沿用网站蓝色／海洋青色；已走过的格子有明确实心，未来格子留白；今天与愿望使用暖金色。
- 正文沿用网站现有中文字体，叙事标题可使用系统宋体作为辅助，不下载新字体。主要标题和关键数字有足够字号，辅助说明保持低对比但可读。
- 角色为统一的透明 PNG 图集，七阶段各有四帧动作，可直接绘入分享 PNG。来源和完整生成提示见 `2026-11-03-life-character-art.md`；不添加与内容无关的循环漂浮或粒子。
- 分享图不依赖第三方图片、外部字体或网站动态背景，保证离线绘图与导出稳定。

## 方案比较与实现方向

用户已选定带阶段角色的横向旅程转纵向全景，纯统计面板不能满足本次目标。将整段做成视频会失去出生日期、日周切换、全屏适配和动态海报的自由度，因此采用可交互的网页舞台。

沿用 Canvas 负责三万格及可复用的导出绘制，DOM 图片图集负责角色，DOM 负责阶段文案与控制；共享日期、阶段与格子布局模型，确保舞台、全屏、PNG 结果一致。完整地面缓存留白与走过两层，近景只补绘视野内同一坐标的石片细节。全部用 DOM 格子会增加手机负担；引入游戏引擎对这套二维体验过重。这是实现者推荐的技术选择，不是用户指定的库。

## 边界与限制

- 输入、日期计数、预计寿命 1–120 岁等口径沿用现有已验证模块；不重写为年龄乘 365 的近似算法。
- 日／周、主题、窗口宽高、跨天变化及关闭动态不会留下过期的角色位置、格子数或海报预览。
- 提交新数据、重播、切换、打开／关闭全屏都应取消旧动画，不让多个角色或旧画布残留。
- 预计寿命已过时格子全完成，保留「可以调整预计寿命，继续看未来」的语气；允许填写未来愿望，不制造倒计时终结页面。
- 无 JS 时仍明确提示无法计算，不提交生日；无 Canvas 时有清楚提示。
- 不变更站点导航布局、不混入共享工作区其他任务的改动，不自动提交或发布。

## 验收

1. 阶段生日边界、闰日、阶段截断、跨阶段周与已经超过设定终点都有日期测试。
2. 提交后可看到爬行／行走、阶段替换、停在今天和横向到纵向变化；跳过、重播和减少动态可用。
3. 日／周自由切换不清空生日、寿命与愿望，角色停驻的公历日期保持一致。
4. 320px 手机、常见桌面、横竖屏全屏图均完整显示所有格子，没有内部拖动条，最后一格与今天都在范围内；键盘关闭、焦点回归与数字查询可用。
5. PNG 实际解码检查尺寸及非空像素；日周两种海报的计数、阶段与全部格子完整，长愿望不会溢出；出生日期默认隐藏，示例有标注。
6. 下载可用；原生分享可用／不支持／用户取消三条路径均不报错；不上传生日或愿望。
7. 完成整站测试、Astro 类型检查、构建及链接检查；人工查看旅程关键帧、全屏与海报。
