# 个人小宇宙：博客设计稿

日期：2026-11-02
状态：用户已认可页面原型；2026-11-02 补充背景场景切换和文章阅读量需求。

## 1. 目的与已确定的方向

建立一个以写作为核心的个人博客，兼顾个人介绍和有辨识度的背景动画。内容可以包括日记、感悟、经验与工具技巧，不限定领域。

用户已选择 Astro 定制路线，并接受读者登录 GitHub 后发表评论。网站由 GitHub Pages 托管，不维护自己的服务器；文章使用 Markdown，评论使用 giscus。

第一版成功的标准：新文章发布步骤简单，访客容易找到和阅读内容，手机浏览舒适，背景动画形成个人风格，评论可以正常使用。

## 2. 方案比较与选择

| 方案 | 优点 | 取舍 | 结论 |
| --- | --- | --- | --- |
| Astro 定制 | 能自由设计文章、短记与动画；输出静态页面 | 初期需要定制开发 | 用户已选择 |
| Hugo 加现成主题 | 生成快，成熟主题多 | 外观和交互受主题影响 | 备选 |
| Jekyll 加现成主题 | 与 GitHub Pages 集成方便 | 定制丰富交互的工作量相对较大 | 备选 |

确定组合：Astro + Markdown + GitHub Actions + GitHub Pages + giscus。优先采用 Astro 自带能力、CSS 和少量原生 JavaScript，避免为简单交互引入完整前端运行时。

## 3. 内容与写作

### 内容组织

- 先设置三个可扩展分类：日常、随想、实践。每篇文章选择一个分类。
- 标签按需填写，不预先建立大量空标签。
- 内容有长文和短记两种形态，共用内容集合与详情页体系。
- 长文在首页展示标题和摘要；短记展示简短正文，超出展示长度后进入详情页阅读。
- 分类对应内容主题，长文或短记对应展示形态，两者互相独立。

### 文章字段

Markdown frontmatter 支持：标题、发布日期、更新时间、固定 slug、分类、标签、内容类型、摘要、草稿状态、是否开启评论。封面可选，不强制填写。

- 标题、发布日期、固定 slug、分类为必填项；内容类型默认长文。
- 日期支持带时区时间，统一按 Asia/Shanghai 展示。
- 摘要可选，缺省时从正文生成纯文本摘要。
- 长文默认开启评论，短记默认关闭，允许逐篇覆盖。
- 草稿不进入正式构建产物、搜索索引、RSS 或站点地图；仅在本地开发时预览。
- 第一版不做定时发布，正式发布由草稿标记和提交决定。
- 固定链接统一为 `/posts/<slug>/`，不依赖分类和发布日期；发布后保持 slug 稳定，修改时需要重定向旧链接。

### 发布流程

本地编辑 Markdown 或在 GitHub 网页编辑 → 提交到发布分支 → GitHub Actions 检查并构建 → 将构建结果发布到 GitHub Pages。

每篇文章的图片保存在仓库中。支持插入图片、链接、引用、列表、代码和表格，提供一份可复制的文章模板及简短写作说明。第一版不设置后台编辑器。

## 4. 页面结构

| 页面 | 内容与作用 |
| --- | --- |
| 首页 | 名字、一句介绍、轻量宇宙背景、最近文章与短记；首屏内能看到内容入口 |
| 文章详情 | 标题、日期、分类、文章阅读量、正文、长文目录、上一篇与下一篇、可选评论 |
| 归档 | 按年份和日期整理所有已发布内容，可进入分类与标签列表 |
| 分类与标签列表 | 查看同一主题下的文章，复用文章列表样式 |
| 关于我 | 一段介绍、关注的话题、可选经历与公开联系链接 |
| 搜索 | 搜索标题和正文，显示文章标题、命中摘要与链接 |
| 404 | 明确说明页面不存在，提供首页和归档入口 |

主导航保持为首页、归档、关于我，并提供背景场景切换、搜索和深浅色切换入口。分类与标签通过内容和归档进入，不占满导航。

首页以清晰的文章列表为主，不设置占满屏幕的欢迎页，不强制文章统一配图。第一版每页展示约 10 条内容，使用静态分页。

移动端目录折叠展示；桌面端长文可使用侧边目录。正文宽度以约 34–38 个汉字为目标，正文基础字号约 17–18px、行高约 1.8–1.9，实际以手机和桌面预览校正。

## 5. 视觉方向：有生命感的个人小宇宙

用户已认可原型的页面布局与总体风格；配色和动效的实现细节以实际预览校正。

### 色彩与文字

- 星空底色：`#101D35`，用于深色模式的页面背景。
- 深色表面：`#1A2B46`，用于导航、搜索等必要容器。
- 浅色底色：`#F6F8FC`，用于浅色模式背景。
- 深色文字：`#22324A`，用于浅色模式正文。
- 浅色文字：`#E8EDF5`，用于深色模式正文。
- 星光蓝：`#8DBAFF`，作为深色模式重点色；浅色模式链接使用更深的蓝色并检查对比度。

中文采用本机可用的清晰无衬线字体组合，优先系统字体，避免首次加载下载庞大的中文字体包。代码使用等宽字体。标题和正文通过字号与字重形成层级，不堆叠装饰性字体。

深浅色默认跟随系统，用户选择后保存到本地。背景场景独立于深浅色：深空和沙滩均支持浅色与深色阅读模式，不强制把某种场景绑定到一种明暗模式。

### 背景场景切换

用户要求通过按钮切换页面背景，例如深空与沙滩。第一版提供两种场景，初始默认深空，记住访客在当前浏览器中的选择。

- 页头提供显示当前场景名称的按钮；点击展开包含缩略预览的场景选择面板。
- 深空：蓝色背景、星点与缓慢的轨道；沙滩：海天、沙岸和轻微潮汐动效。
- 切换时协调页面底色、重点色与首页插画；文章、归档、关于我也采用相应的背景配色。保持原有排版、文章内容和阅读进度。
- 动画开关同时控制当前场景的星点或潮汐，尊重系统减少动态效果设置。
- 场景与深浅色、动画选择存入本地；本地存储不可用或数据损坏时正常使用默认配置。
- 选择面板支持键盘操作、Escape 关闭、点击外部关闭，以及关闭后合理返回焦点。当前选项有明确的文字与选中状态。
- 手机端可用；面板不越出屏幕，不遮挡正文操作。暂不添加自定义图片上传或自动轮播。
- 原型阶段采用 CSS 插画，不依赖外部照片或视频。正式实现可沿用轻量插画方案。

### 背景动画

每次只启用当前场景的主要视觉效果：深空采用缓慢移动的星点和少量轨道，可增加低幅度鼠标视差；沙滩采用缓慢的潮汐变化。第一版不做复杂 3D 场景。

- 背景不阻挡文字、按钮和链接，不参与指针事件。
- 首页动画较完整；文章页减弱，不在正文背后出现明显闪动或追随效果。
- 手机减少粒子数量，并移除鼠标交互。
- 提供明确的动画开关，保存选择。
- 尊重 `prefers-reduced-motion`，默认使用静态背景；页面不可见时暂停绘制。
- 动画脚本延后加载；脚本失败或关闭时，文章、导航和分页仍然可用。
- 优先用 Canvas 2D 绘制有限数量的星点，不为背景引入 Three.js。

## 6. 评论：giscus

使用公开 GitHub 仓库的 Discussions 保存评论，通过 giscus 嵌入文章页面。访客无需登录即可查看评论，登录 GitHub 后发表评论、回复和回应。

- 以稳定的文章 pathname 关联讨论，所有链接包含正确的 GitHub Pages 基础路径。
- 为博客评论建立专用 Discussion 分类，减少和其他讨论混杂。
- 评论区域接近视口时再加载，主题与网站同步。
- 对关闭评论的文章不加载评论组件。
- 管理者在 GitHub 中管理、删除评论或锁定对应讨论。
- 评论不可用时保留文章阅读，并提供可用的 GitHub 讨论入口或文字提示。
- 使用标准 giscus 配置，不公开密钥，不额外索取 GitHub OAuth 权限。

正式接入需要仓库公开并启用 Discussions，仓库管理员安装并授权 giscus GitHub App，之后填写生成的 repo ID、category ID 等公开配置。第一版开发可先使用占位配置；未完成配置时显示清晰说明，不显示损坏的评论框，不宣称评论已经启用。

### 文章阅读量

用户只需要每篇文章的阅读量。放在文章详情页的发布日期、预计阅读时间旁边，显示为“阅读 128 次”；不展示全站访问量或访客人数。

- 正式站点接入适合静态网站的第三方计数服务，优先评估不蒜子，无需自建后端。
- 统计口径为页面浏览次数 PV，不将其标成独立读者人数或完整阅读人数；重复访问或刷新可能再次计数。
- 每篇内容根据自己的正式固定链接独立统计，覆盖文章和短记详情，不在首页、归档或关于我触发文章阅读计数。
- 正式 Astro 页面使用独立 URL；当前原型通过同一页面切换内容，不能把该预览地址的访问量冒充成各篇文章的真实计数。
- 原型只演示位置与样式，数字明确标为“示例”，不向统计服务发送预览访问，也不靠浏览器本地存储模拟真实阅读量。
- 真实统计脚本只在正式发布的文章详情页加载。切换背景、明暗或开关动态，不重复触发计数。
- 加载时显示“阅读 — 次”；服务超时或不可用时保留占位，不显示虚构的零，也不影响正文与评论。
- 服务返回真实数字后再展示；数字使用等宽数字排版，窄屏允许整项换行，兼容两种场景与深浅色。
- 正式接入时验证项目基础路径、文章 slug 和 URL 参数的处理，确保同一篇文章不会错误拆分或与其他文章合并计数。

## 7. GitHub Pages 与构建

- Astro 使用静态输出，不依赖 SSR、API 服务或数据库。
- GitHub Actions 安装依赖、执行 Astro 检查、构建静态站点，并通过 GitHub 官方 Pages Actions 发布。
- 流水线固定 Node 的受支持 LTS 版本，并使用锁文件安装依赖；具体版本由开发时根据 Astro 支持范围确定。
- 发布流程限制在选定发布分支；拉取请求可检查构建，不直接发布。
- 同时兼容用户站点 `username.github.io` 和项目站点 `username.github.io/my-universe/`。统一配置 `site` 与 `base`，覆盖导航、文章、分页、图片、搜索、RSS、站点地图和评论映射。
- 在确定真实仓库信息前不编造线上地址。暂不要求购买域名，之后可绑定。
- 使用仓库对应的 GitHub Pages HTTPS 地址。无需用户维护服务器。

## 8. 第一版功能与边界

第一版包含：文章与短记、分类与标签、归档、静态分页、关于我、静态全文搜索、RSS、站点地图、代码高亮、长文目录、深浅色主题、深空与沙滩背景切换、受控背景动画、按文章配置的 giscus 评论、文章阅读量。

搜索建议采用构建后的 Pagefind 静态索引，中文检索效果在实现时用真实中文样文验证。搜索面板在用户打开时再加载相关资源；搜索不需要外部服务器。

第一版不做访客账号体系、后台 CMS、点赞排行榜、全站访问量或访客人数展示、音乐播放器或大型 3D 交互。这些不影响目前的写作目标，需要时单独评估。

页面标题、描述、canonical、RSS 与站点地图使用真实站点配置。除文章阅读计数外，不额外接入分析统计服务。

## 9. 验收方式

- 用一篇中文长文、一则短记及一篇草稿验证内容展示、分类、归档、分页、搜索和 RSS；演示内容必须标明为示例，不冒充用户经历。
- 验证代码、表格、长链接和图片在窄屏不会破坏正文布局。
- 在手机和桌面检查首页、文章、归档、关于我与搜索的实际效果。
- 验证深浅色主题、键盘操作、可见焦点、动画开关、减少动态效果设置以及禁用 JavaScript 时的基本阅读能力。
- 验证两种场景与深浅色的四种搭配、跨页面保持场景、刷新后恢复选择，以及本地存储不可用或内容损坏时的回退行为。
- 在非根路径构建下检查导航、资源、分页、RSS、搜索和文章链接。
- giscus 配置就绪后，在正式站点验证查看、登录及发表评论；配置未就绪时将此项明确列为待接入。
- 阅读量接入后验证两篇文章分别计数、其他页面不触发文章计数、服务失败不影响阅读，以及本地原型明确标注示例数字。
- 发布前检查正式产物中不包含草稿、虚构个人资料或未替换的站点配置。

## 10. 留给开发与上线时确定的事项

开发者可自行确定具体组件组织、样式实现、粒子数量、列表摘要长度、目录出现阈值和可访问的配色细节，并以实际预览校正。

公开昵称、自我介绍、头像与联系链接尚未提供：开发阶段使用明确的可替换占位内容，不填写虚构身份。真实 GitHub 仓库地址、发布分支、Pages 设置与 giscus 配置在接入时从现有仓库获取或由用户提供；缺少这些信息不妨碍先完成本地静态页面。

当前已按本设计完成 Astro 静态网站代码与本地验证，实施记录见同目录对应计划。网站尚未上线；GitHub Pages 设置、giscus App 授权与公开配置在实际发布接入时完成。
