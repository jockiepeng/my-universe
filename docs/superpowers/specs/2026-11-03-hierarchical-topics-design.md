# 分层主题分类设计

## 目标与已确认方向

直接升级现有分类，用明确的内容主题组织文章；不再使用“随想”分类。读者选择父主题时能找到其所有子主题的内容，选择子主题时能进一步缩小范围。

## 方案选择

- **升级现有分类（用户已选择）**：以分层主题替换“日常 / 随想 / 实践”，继续使用文章的 `category` 字段，避免同时维护两套分类。
- 保留原分类并另加主题：可分别表达文章风格与内容领域，但归类和界面重复，未采用。

## 建议的主题与内容迁移

```text
技术
├─ AI           现有三篇技术文章
├─ Go           预留，暂无文章
└─ 数据库        预留，暂无文章
生活
└─ 人际关系      《好人缘，是这样慢慢养成的》
```

用户已确认按此方案调整。每篇文章填写一条完整主题路径，例如 `category: 技术/AI`；标签继续用于 Codex、Skill 等交叉关键词。主题集中配置，支持后续增加层级，未知路径在构建时给出错误。

## 浏览与筛选

- 根据用户进一步纠正，首页左侧只显示“全部 + 一级分类”，右侧保留原有文章列表、介绍与标签侧栏。选择一级分类后，在文章列表上方显示该分类的“全部 + 子分类”；点击子分类更新列表，一级分类仍保持选中。切换一级分类时默认选择其“全部”，点击左侧“全部”则隐藏子分类行。
- 在 900px 及以下的窄屏，一级分类移到原有内容上方，避免新增左栏挤压文章；原有文章区与右栏沿用各自的响应式布局，子分类仍位于文章列表前。归档与静态主题页保留分层主题入口。暂无文章的主题暂不出现在导航中。
- “技术”包含技术本身和全部后代主题的文章；“技术 / AI”包含该主题及其后代。匹配完整路径边界，避免误匹配同名前缀。
- 首页点击分类即时筛选全站公开内容，不局限于首页当前页；可叠加“全部 / 文章 / 贴图”筛选。主题链接同时提供对应静态主题页，禁用 JavaScript 时仍可导航。主题页也可叠加类型筛选。
- 主题页显示当前主题、父级路径、可用子主题和文章数量。文章元信息显示可分别点击的主题路径。
- 首页默认继续使用原有分页，启用分类或类型筛选时显示全站匹配记录并暂时隐藏分页，重置后恢复当前页。主题页与现有分类页一样，列出该主题的全部记录。筛选状态同步到 URL，刷新及浏览器前进后退可恢复。

## 约束与兼容

沿用 Astro、Markdown 和静态托管，不增加依赖。主题 URL 使用稳定的英文层级，例如 `/categories/technology/ai/`；文章 slug、正文和资源路径保持稳定。旧分类地址 `daily`、`thoughts`、`practice` 分别提供静态跳转至生活、生活、技术，并有可点击的目标链接。

同步更新文章校验、首页、归档、主题页、元信息、RSS、站点地图和写作指南；搜索索引仍只收录正式文章。不实现多主题归属、主题管理后台或自动猜测归类。

## 验证

验证父子聚合、同名前缀边界、主题路径和空主题导航；运行仓库现有测试、Astro 检查、构建及产物链接检查；在桌面和手机宽度检查主题入口、完整主题结果及类型筛选组合。
