# 写作与发布

## 先写文稿

还没整理好的想法和初稿放在仓库根目录的 [`drafts/`](../drafts/README.md) 中，直接写 Markdown 正文即可，无需文章配置。这个文件夹不参与博客构建。

之后可以让 AI 根据指定文稿润色，在 `src/content/posts/` 中生成正式文章，先设为 `draft: true`，确认后再发布；原始文稿保留。

## 新建文章

在 `src/content/posts/` 新建 `.md` 文件，公开链接由 `slug` 决定。复制以下模板：

```yaml
---
title: 今天想记下的事
slug: something-to-remember
date: 2026-11-02T20:00:00+08:00
category: 生活
tags: [生活]
kind: post
summary: 一句简短介绍；这一项也可以省略。
draft: true
---
```

在 frontmatter 下写 Markdown 正文。准备发布时改为 `draft: false`，提交并推送到发布分支即可。`draft: true` 只在本地开发模式可见；正式构建、搜索、RSS、站点地图都不包含它。

- `slug`：必填，小写英文、数字和连接符，全站唯一。发布后保持稳定，例如 `/posts/something-to-remember/`。
- `date`：必填，作为永久创建时间，填写完整的 `2026-11-03T18:30:45+08:00`（含时分秒和时区）；列表、归档与 RSS 按创建时间倒序，修改旧文不改变排序。页面按北京时间显示，不支持定时发布。历史文章只有日期时用当天 `00:00:00+08:00` 占位，并标记 `datePrecision: day`，不把零点当作已知实际创建时刻。
- `category`：填写完整主题路径，例如 `技术/AI`、`技术/Go`、`技术/数据库`、`生活/人际关系`；也可直接归入父分类 `技术` 或 `生活`。路径中的 `/` 表示父子关系，不需要在文章中重复填写父分类。
- `tags`：可省略，支持中文；不使用 `/`、`\`、`?`、`#`、`%` 等路径保留字符。
- `kind`：`post` 为文章，`photo` 为贴图；省略时默认文章。仅支持这两种类型。
- `summary`：可省略，网站会从正文生成摘要。
- `comments`：可设 `true` 或 `false`；文章默认开启，贴图默认关闭；需全站完成 giscus 配置。
- `updated`：可选，显式指定最近编辑时间。历史文章已初始化为创建时间。以后只改正文或元信息、保留该字段不变时，正式构建会读取该文件最近一次修改的 Git 提交时间作为最近编辑时间；本地未提交修改使用文件修改时间，不会因重新部署或打开页面而刷新。确实需要指定编辑时间时，修改此字段优先生效。新文章未编辑过时默认等于创建时间。没有 Git 历史时回退到 `updated` 或 `date`；Actions 已配置完整历史。
- `cover`：普通文章可选，本地图片相对路径，例如 `./images/my-photo.jpg`；建议填写 `coverAlt` 描述图片。贴图统一使用 `images`，不设置 `cover`。
- `thumbnail`：可选，指定文章列表右侧的缩略图，例如 `./images/my-photo.jpg`；建议填写 `thumbnailAlt` 描述图片。它只用于列表，不会在正文顶部重复插图。未填写时依次使用 `cover`、`images` 第一张；都没有则保持纯文字列表。正文内有图片的普通文章，可将其中一张的相对路径填在这里。
- `example`：现有样文使用 `true` 标为示例；自己的文章无需此字段。

生活类目前有「人际关系」和「运动」子分类。桌球贴图使用 `category: 生活/运动`，会同时出现在「生活」父分类和「运动」子分类下；新增主题要先在 `src/lib/topics.mjs` 配置。

自动编辑时间跟踪的是 Markdown 文件。只替换同路径图片、或重命名文章文件时，请同时填写 `updated`，使编辑记录与实际修改一致。

## 贴图：上方多图，下方文字

设为 `kind: photo`，在 `images` 中按顺序列出 1–9 张图片，每张都填写 `src` 和图片说明 `alt`。首页、分类和标签等文章列表在文字右侧展示第一张图片的缩略图，也可用 `thumbnail` 单独指定；首页可以单独筛选“贴图”。进入详情页后，头部一次展示一张图片，下方显示完整文字。

```markdown
---
title: 散步时看到的风景
slug: a-walk-in-the-evening
date: 2026-11-02T20:00:00+08:00
category: 生活
tags: [散步]
kind: photo
draft: true
images:
  - src: ./a-walk/01.jpg
    alt: 河边的夕阳
  - src: ./a-walk/02.jpg
    alt: 路边的一棵树
---

在这里写文字，换行会保留。
这一行仍在同一段里。

空一行开始新的段落。
```

多图支持左右滑动逐张查看；电脑还可使用上一张、下一张按钮，或聚焦图片区域后使用方向键、Home / End 切换。显示当前张数，不自动播放。图片保持比例完整展示，点击可在新标签页查看原图。禁用 JavaScript 时仍可横向滚动浏览。

贴图正文是纯文字，不解析 Markdown 或 HTML。不要在正文中写 `![图片](路径)` 或 `<img>` 等图片标记，构建时会提示改放到 `images` 中。普通文章仍可在正文中插图。

可以复制 [`drafts/贴图模板.md`](../drafts/贴图模板.md) 开始写，图片放在文稿旁的同名文件夹。让 AI 整理为正式贴图时，一起迁移图片并修正 `images` 相对路径，先保留 `draft: true`，确认后再发布。

## 分类与筛选

分类集中定义在 `src/lib/topics.mjs`，每项包含中文路径 `path`、显示名称 `label`、稳定英文地址 `slug` 和说明 `description`。新增子分类时同时配置父分类，例如先有 `技术`，再添加 `技术/Go`；多级分类也遵守这个规则。未知分类会在构建时提示错误。

首页左侧显示“全部 + 一级分类”与篇数，原有介绍和标签仍位于右栏。选择一级分类后，文章列表上方显示该分类的“全部 + 子分类”：其中“全部”包含该一级分类下所有内容，点击子分类可进一步筛选；切换一级分类会重置子分类，点击左侧“全部”会隐藏子分类行。手机上一级分类移到列表上方。

分类还可叠加“文章 / 贴图”筛选。筛选覆盖全站公开内容，启用时显示全部匹配结果并隐藏原分页，重置后恢复当前页。地址栏保存筛选状态，刷新和前进后退可恢复。没有文章的分类暂不出现在筛选入口中。

分类回答“这篇内容属于哪个主题”，`tags` 则补充 Codex、Skill、沟通等关键词，允许跨主题寻找内容。文章元信息中的各级分类可分别点击，直接进入对应主题页；禁用 JavaScript 时，首页分类链接也会打开静态主题页。

现有四篇技术文章归为 `技术/AI`，好人缘贴图归为 `生活/人际关系`。旧的分类链接会跳转到新分类，文章本身的地址保持不变。

## 图片、目录与代码

图片放在文章旁的 `images/` 文件夹，用相对路径插入：

```markdown
![对图片内容的描述](./images/my-photo.jpg)
```

`##` 和 `###` 标题自动生成目录，手机端默认收起。带语言名称的代码块自动高亮。长表格与代码块在手机上可横向滚动，正文保持在屏幕宽度内。

## 个性化

站名、描述和公开联系链接在 `src/site.config.ts`；自我介绍在 `src/pages/about.astro`。先替换示例介绍，将示例文章改为自己的内容或删除。

访客可切换深空与沙滩、深浅色和背景动态。偏好保存在当前浏览器，不修改仓库，也不需要登录。

## 发布前

运行 `npm run verify`。确认私密内容没有误设为 `draft: false`，图片和链接正确；随后提交到 GitHub。Pages 工作流发布后，检查实际域名上的搜索、阅读量与评论。
