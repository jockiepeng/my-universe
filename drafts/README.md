# 文稿箱

这里用来存放还没整理成正式文章的想法、随手记录和初稿。

## 怎么写

- 在这个文件夹下新建 Markdown 文件，例如 `2026-11-02-我的想法.md`。
- 直接写正文即可，不需要填写正式文章的标题、分类、日期等配置。
- 图片可以放在同名文件夹里，例如 `我的想法/截图.png`，在文稿中用相对路径引用。

可以从下面几个问题开始写，也可以完全自由记录：

```markdown
# 暂定标题

## 我想说什么

## 事情的经过 / 我的做法

## 遇到的问题和收获

## 还需要补充的资料
```

## 交给 AI 整理

如果想写“上方多图、下方文字”的贴图，可以复制 [贴图模板.md](贴图模板.md)，在 `images` 里填写图片，在正文里只写文字；图片放在文稿旁的同名文件夹。

写好后，可以这样告诉 AI：

> 请根据 drafts/文件名.md 润色成一篇博客文章，保留我的观点和语气，不编造经历或数据；不确定的地方标出来。将整理后的文章放入 src/content/posts/，补齐文章配置，先设为 draft: true，保留原始文稿，等我确认后再发布。

贴图可以这样说：

> 请根据 drafts/文件名.md 整理成 kind: photo 的贴图，保留图片顺序和我的语气，将所有图片配置在 images 中，正文只保留文字。迁移文稿和图片到 src/content/posts/，修正相对路径，先设为 draft: true，并保留原稿。

本文件夹不参与博客构建，不会出现在博客页面、站内搜索、RSS 或站点地图中。原稿、图片和子文件夹默认被 Git 忽略，仅保留在本地；本说明和 `贴图模板.md` 继续随仓库提交。

不要使用强制添加将私人文稿提交到仓库。历史上已经提交的内容仍可能保留在旧提交中，加入忽略规则不会清除历史记录。
